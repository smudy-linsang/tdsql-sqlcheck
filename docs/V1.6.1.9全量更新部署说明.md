## 一、 版本核心变更与架构演进总览 (升级至 V1.6.1.9)

### 1. TDSQL 分片表与广播表建表语法全量支持（核心修复）
- **支持内核 HASH 分片语法**：全面解析 `TDSQL_DISTRIBUTED BY HASH(col)`，精准提取分片键并与主键/唯一索引匹配，彻底消除误报。
- **支持全局广播表哨兵**：精准识别 `shardkey=noshardkey_allset`，规避将其当作真实列名字段查主键的逻辑漏洞。
- **严格安全防御**：
  - 尾部锚定：表选项仅在列定义闭括号后检索；
  - 词法清洗：注释（`-- `、`/* */`、`#`）与单双引号字面量清洗，防注入/防绕过；
  - 唯一索引独立检查：每一个唯一索引均严格执行包含分片键检查。

### 2. 部署流程与密钥继承自动化加固
- `install.sh` 脚本在多版本目录切换时，自动同步历史版本的 `encryption.key` 并固化 `TDSQL_ENCRYPTION_KEY` 至 `/opt/tdsql-sqlcheck/.env`，确保 119 个实例连接无缝解密。

### 3. API 健壮性提升
- 在线元数据审核接口对于目标实例网络/认证失败场景提供标准化友好提示，避免 500 异常。

## 二、 全量更新操作四步法

### 步骤 1: 上传介质与环境准备
在具备 sudo 权限的运维机上，将发布包上传至 `/tmp`：
```bash
cd /tmp
tar -zxvf tdsql-sqlcheck-v1.6.1.9-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.1.9
```

### 步骤 2: 执行全量标准安装
```bash
sudo ./deploy/install.sh --install-dir /opt/tdsql-sqlcheck
```
*安装脚本会自动执行：*
1. 创建 `/opt/tdsql-sqlcheck/releases/v1.6.1.9` 目录；
2. 离线安装 Python 依赖库；
3. 保留 `/opt/tdsql-sqlcheck/.env` 既有配置并自动继承/固化解密密钥；
4. 切换软链 `/opt/tdsql-sqlcheck/current -> releases/v1.6.1.9`；
5. 重载并重启 `tdsql-sqlcheck.service` 系统服务。

### 步骤 3: 自动化验收核验
```bash
sudo /opt/tdsql-sqlcheck/current/deploy/verify_deploy.sh
```
确保以下各项全部为 `[PASS]`：
- 进程状态：Active (running)
- 监听端口：8000 正常监听
- 版本比对：`1.6.1.9`
- 规则加载：119 条规则完整就绪

### 步骤 4: 浏览器业务功能验收
1. 访问系统：`http://<服务器IP>:8000`，登录页与主界面版本显示为 **V1.6.1.9**；
2. 实例管理：测试现有实例连接是否全部正常连通；
3. 在线元数据审核：选择分片表/广播表执行“拉取元数据并审核”，验证原误报项已彻底消除。

## 三、 快速回滚方案 (Rollback)

若遇到异常需要快速回退至上一版本：
```bash
sudo /opt/tdsql-sqlcheck/current/deploy/rollback.sh --install-dir /opt/tdsql-sqlcheck
sudo /opt/tdsql-sqlcheck/current/deploy/verify_deploy.sh
```
回滚脚本将秒级回拨软链至上一版本（如 v1.6.1.8 或 v1.6.1.6），无任何数据丢失。
