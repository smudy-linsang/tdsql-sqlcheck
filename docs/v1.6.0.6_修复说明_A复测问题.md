## 二、修复明细

### 2.1 A-P1-01 导入预检枚举对齐 ≥1 成功口径（必修）

`backend/services/zk_connection_import_service.py::_list_business_databases`：

- 逐端点捕获异常 `continue` 不再 raise；
- 0 个成功 → `NO_AVAILABLE_PROXY`（不造假数据）；
- 有失败或目录不一致 → **取并集**，来源标 `proxy_show_partial`；
- 全部成功且一致 → `proxy_show`；
- 返回值由 `list[str]` 改为 `(list[str], str)`，`build_preview` 调用点同步更新。

**为什么保留并集而不是交集**（采纳 A §2.3 的判断）：多算的库用户在预览里看得见、可以不勾（可见的错误）；漏算的库用户无从得知（不可见的错误）。R-15 失败非对称，宁可多给。

### 2.2 A-P1-02 配置保存 null 端口容错 + 422 可见（必修）

- 后端 `ZKDiscoveryConfigRequest.monitor_port` 改 `Optional[int]` + `field_validator(mode="before")` 把 `None`/`""` 归一为 0；
- 前端 `responseMessage()` 新增**数组型 detail 分支**：取首条 `loc`（去掉 `body` 前缀）+ `msg` 展示，今后任何 422 都有字段级指向；
- `zkConfigForm.monitor_port` 保留 null 形态（空输入体验），由后端容错兜底。

### 2.3 A-P1-03 shell 驱动分布式实例丢失（同批修）

- `deploy/tdsql_inventory.sh`：`gid="${entry%|*}"` → `gid="${entry%%|*}"`（首个分隔符之前）；
- 同脚本内嵌 Python 段：`len(parts) != 5` 的静默丢弃改为打 `[WARN] inventory 记录字段数异常`——日志计数与输出对不上时必须留痕；
- **内网核对动作仍然有效**（A §7）：若内网在用 shell 驱动，请按 A 给出的两步对账一次。

### 2.4 A-P2-01 降级可见

- 富集侧与预检侧均改为 `failed > 0 → proxy_show_partial`（此前仅目录不一致才标）；
- `tests/test_zk_v1605.py` 原断言 `source == "proxy_show"` 同步改为 `proxy_show_partial` 并注释取舍原因；
- 前端发现列表与导入预览的「业务库」列：`databases_source` 含 `partial` 时挂 warning 型 `el-tag`「部分 Proxy」+ tooltip「部分 Proxy 未响应，列表可能不全」。

### 2.5 A-P3-01 主 Proxy 真正前移

`zk_scan_enrich_service._proxy_endpoints` 与 `zk_connection_import_service._proxy_endpoints` 两处同改：先从列表移除主 Proxy 再插首位。主 Proxy 是已做网段适配、已知可达的端点，排最前可避免死 Proxy 先耗一轮连接超时。

## 三、§7-6 版号问题处置（初判更正）

**初判更正**：本报告初版基于 `8fb1273` 曾把 VERSION 改为 1.6.0.51 的 git 证据判为"不认可"。
经项目负责人确认：**1.6.0.51 确系笔误**——当时给 G 的发布命令误写为 "1.6.0.51"（本意 1.6.0.1），
其后已按 "1.6.0.1" 重新打包发布。git 里的 1.6.0.51 只是那次误发布的残留，不能反证其正当性。

**处置**：`docs/v1.6.0.51_upgrade_manual.md` 与 `docs/V1.6.0.51全量更新部署说明.md` 文首已加
作废标注（笔误背景 + 实际对应 V1.6.0.1 + 内网若持有 1.6.0.51 包则与 1.6.0.1 等价），
目标版本行更正为 V1.6.0.1。文件名保留不改，理由：

1. 误发布的包确实以 1.6.0.51 之名交付过，内网若持有该包，需能按名找到对应文档看到标注；
2. 直接改名/删除会抹掉这次版号事故的追溯链路；
3. A 原文建议改为 "V1.6.0.5"，但按负责人确认的史实，实际版号应为 **1.6.0.1**；且 1.6.0.5 与 1.6.0.51 仅一位之差，改名反而易造成新混淆，故标注中明确指向 1.6.0.1 配套文档。
