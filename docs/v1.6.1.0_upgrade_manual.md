## 一、 版本核心变更与架构升级总览 (V1.6.0.7 ➔ V1.6.1.0)

从 V1.6.0.7 全量升级至 V1.6.1.0，系统完成了以下四大核心能力提升与细节打磨：

1. **ZooKeeper 探查失败语义细化 (Errno 归类)**：
   - 将无法探查业务库的具体原因精确分类（如 1045 权限错误统一映射为 `NO_BUSINESS_USER`）；
   - 前端清晰呈现“未创建监控/业务用户”提示标签与 Tooltip 帮助，不再模糊提示一般错误。

2. **系统管理库精细过滤与屏蔽**：
   - 将 `sysdb` 等系统管理库统一加入 `SYSTEM_DATABASES` 过滤黑名单，防止误选或污染业务库视图（手工覆盖路径保持灵活性）。

3. **预检状态列表可读性重构**：
   - 改进自动发现预检列表中包含的枚举状态映射，更加直观呈现各 Proxy 端点联通性与业务库就绪度。

4. **全量自动化测试套件通过 (1283 用例全过)**：
   - 新增 6 条 ZK 探查语义与系统库过滤专项单元/集成测试，回归测试实现 1283 PASS / 0 FAIL / 0 SKIP。

## 二、 核心重点：元数据库（System Meta-Database）变更与自动迁移详解

**在升级至 V1.6.1.0 过程中，后台服务启动时会自动安全地应用全套增量 Schema 迁移文件（v7 原始慢日志、v8 ZK配置、v9 连接唯一约束、v10 扫描富集与留痕）以及 `migrator.run_migrations()`，无需运维人员手动执行 DDL 脚本。**

元数据库包含历史连续演进架构：
- **v7 架构**：5 张原始慢日志系统表（`slow_log_sources`, `slow_log_source_nodes`, `slow_log_cursors`, `slow_log_events`, `slow_log_runs`）；
- **v8 架构**：`zk_discovery_config` 表存储 ZK 节点配置、Proxy 映射规则、段替换与富集参数；
- **v9 架构**：`tdsql_connections` 增加 `(host, port, database)` 联合唯一索引 `uk_host_port_database`（修正去重判据，绝不按同名误删）；
- **v10 架构**：`zk_discovery_config` 增加扫描富集配置列（`octet_rules_json`, `enrich_enabled` 等），`zk_discovery_import_items` 增加 `name_source` / `databases_source` 留痕列。

## 三、 全量部署与安装操作步骤（内网运维智能体执行）

### 1. 解压全量发布包与部署预检
```bash
# 解压全量发布包
tar -zxvf tdsql-sqlcheck-v1.6.1.0-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.1.0

# 执行部署预检（要求全 PASS，验证依赖与环境健康）
bash deploy/preflight_check.sh
```

### 2. 配置文件校验 (`deploy/.env`)
核对并更新 `deploy/.env` 配置文件中的元数据库与网络参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Admin@1234
```

### 3. 执行全量安装与服务升级重启
```bash
# 执行安装脚本（停止已有服务、覆盖全量代码、重新安装 wheels 依赖、升级数据库 Schema）
sudo ./deploy/install.sh
```
> ⚠️ **重要提醒**：`kazoo` 为本版必配离线依赖。全量安装时**必须完整运行 `./deploy/install.sh`（或执行 `pip install --no-index --find-links wheels/ -r requirements.txt`）**，切勿仅手动替换代码目录。

### 4. 上线最后自检 (必做步骤)
```bash
# 在目标部署机上运行部署校验脚本
bash deploy/verify_deploy.sh
```
`verify_deploy.sh` 会自动检测 Uvicorn 进程、端口监听、版本比对（输出 `1.6.1.0`）与 `/health` 端点，全部输出 PASS 即代表升级成功。
