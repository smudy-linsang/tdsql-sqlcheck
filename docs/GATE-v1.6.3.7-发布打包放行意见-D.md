## 1. 事实核验：判废脚本会随包发布（已确证）

- `deploy/make_patch.py` 第 90 行 `copy_tree_filtered(ROOT_DIR / "deploy", stage_dir / "deploy")` 为**整目录复制**，因此在生成包的成员清单里**确实存在**：

  ```
  tdsql-sqlcheck-v1.6.3.7-patch/deploy/patch_v1637_source.sql
  tdsql-sqlcheck-v1.6.3.7-patch/deploy/rollback_v1637_source.sql
  ```

- 文档面**已闭环**：《DEPLOY-v1.6.3.7-内网测试环境增量更新部署手册》**铁律 10** 已写明"严禁/无需在测试环境执行任何存量历史数据订正 SQL 脚本"，并明确引用了本判定与 Mr.Linsang 的签署。
- **残留风险**：该脚本自身头部注释仍写着"自动备份、通用正则匹配、动态时区偏移计算、**幂等可重复执行**"，与铁律 10 **直接矛盾**。交付/运维人员若只翻 `deploy/` 目录、不看手册，可能把它当标准动作执行——后果是往生产 `audit_history` 写入畸形文件名（`…_16September52.sql`）并对目标记录再叠加 8 小时。
