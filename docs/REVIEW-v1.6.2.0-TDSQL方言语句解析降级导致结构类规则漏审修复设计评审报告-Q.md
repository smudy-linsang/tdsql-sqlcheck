### 2.2 ADJ-5 交互安全性验证（关键风险点）

设计文档 §6.1 声称"修复后 `parsed.indexes` 仍不产出 UNIQUE 条目，ADJ-5 前提未被打破"。这是本方案**最关键的安全性质**——一旦 UNIQUE 条目进入 `parsed.indexes`，R077 的宽松"或"分支就会被激活，产生漏报。

**独立深入核验**：

| 场景 | 重试后 AST | `parsed.indexes` 中 UNIQUE 条目数 | 判定 |
|---|---|---|---|
| HASH + 反引号 UNIQUE KEY | Create | **0** | 安全 |
| HASH + 裸名 UNIQUE KEY | Create | **0** | 安全 |
| BROADCAST + UNIQUE KEY | Create | **0** | 安全 |

**根因确认**：`_parse_unique_constraint()` 不认识 sqlglot 的 `UniqueColumnConstraint` 节点结构——其 `this` 是 `Schema` 类型而非 `IndexColumnConstraint`，`expressions` 为空列表，导致列提取返回空 dict。这是 **ADJ-5 的既有缺陷**，不是本次重试引入的。设计的"条件性安全"表述准确。

**结论：ADJ-5 前提在本次修复后仍然成立，未踩雷。**

## 3. 设计质量评审

### 3.1 方案选型评价

四个候选方案的对比分析（§2.1）逻辑清晰，选择正确：

| 方案 | 排除理由 | 评价 |
|---|---|---|
| A. 无条件预剥离 | 影响面无法证明为零 | 排除正确 |
| B. 正则兜底补全结构 | 代码量与出错面远大于缺陷本身 | 排除正确 |
| C. 抽取共享清洗工具 | 构成循环导入 | 排除正确 |
| **D. 降级后剥离重试** | **影响面可从控制流证明为零** | **选用正确** |

方案 D 的核心安全性质：`isinstance(ast, exp.Command)` 这道门把剥离正则的不精确性完全隔离在正常语句之外。这是一个**可从控制流证明的零影响保证**，比"实测没发现问题"更有说服力。

### 3.2 优点

| 维度 | 评价 |
|---|---|
| **根因定位** | 精准——不是三条规则的守卫写错了，而是解析器不该降级。修复位置正确（治解析器而非治规则） |
| **爆炸半径控制** | 产品代码仅 1 文件 2 处净增 26 行；不改任何规则、不改 raw_sql、不改 v1.6.1.9 的 distributed.py |
| **ADJ-5 交互分析** | 最出色的部分。不仅做了实测验证，还精确定位了"条件性安全"的根因（`_parse_unique_constraint` 不认识 `Schema` 类型），并设计了 G1★ 断言测试锁定前提 |
| **调研增量** | 发现 `BROADCAST` 同样降级（此前只登记了 `TDSQL_DISTRIBUTED`），扩大了修复覆盖面 |
| **版本号选择** | 取次版本号而非补丁号——因为用户可见的审核结果会明显变化（从"全部通过"变为每张 2-4 条违规）。这是对版本语义的正确理解 |
| **交付说明** | §9 交付说明清单完整，包括"违规数上升是修复的目的而非新引入的缺陷"这条关键告知 |

### 3.3 风险点与对策评价

| 风险 | 等级 | 评价 |
|---|---|---|
| 用户可见违规数上升 | 高（预期内） | 正确。这是修复的目的。设计明确要求写入上线说明，避免用户误以为是新引入的问题 |
| 剥离正则误伤 | 低 | 由 Command 门隔离，4 组边界用例实测均不进入重试。设计正确 |
| ADJ-5 前提被打破 | 中→已排除 | §6.1 实测未踩雷 + G1★ 断言锁定。设计正确 |
| 二次解析性能开销 | 低 | 只在已降级语句上多解析一次。可忽略 |

### 3.4 未发现的问题

以下方面经审查**未发现缺陷**：

- 重试的前置条件 `isinstance(ast, exp.Command)` —— 正确，不得改成无条件剥离
- 重试结果只在 `not isinstance(_retry_ast, exp.Command)` 时才采用 —— 正确
- 重试异常被吞掉并保留原 ast —— 正确（不劣于改前）
- 方言正则覆盖 `TDSQL_DISTRIBUTED BY <method>(...)` 与 `BROADCAST` 两类 —— 正确
- `parsed.raw_sql` 不改 —— 正确（R077/R054 依赖它提取分片键）
- 不向 `table_options` 写入伪造的分片键 —— 正确
- 不改 R037 的 `delete_flags`（NG-6，用户已决策） —— 正确
