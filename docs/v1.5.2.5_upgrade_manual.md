## 一、 版本核心变更与架构升级总览 (V1.2.0.9 ➔ V1.5.2.5)

从 V1.2.0.9 跨越升级至 V1.5.2.5，系统完成了以下四大核心架构升级与能力拓展：

1. **底层存储引擎升级 (V2.1 架构)**：
   - 存储由单机 SQLite 彻底升级为 **MySQL 8.0 / TDSQL 集中式元数据库**，支持连接池复用与高并发能力；
   - 系统表结构扩展至 **27 张核心业务与管理表**。

2. **实例类型感知与多源分级判定 (V1.5 / V1.5.1)**：
   - 引入 **S0 管理员锁定 > S1 Proxy层SQL探测 / S2 ZK管控面 / S3 人工声明** 的四级判定链；
   - 针对分布式与集中式实例，实现 **27 条仅分布式规则 (DISTRIBUTED Scope)** 的自动隔离与精确判定（集中式实例自动跳过 27 条分布式规则，不误报 `R077`）。

3. **ZooKeeper 管控面只读发现 (G10 特性)**：
   - 增加对 ZooKeeper (2118 端口 / `/tdsqlzk`) 的节点自动发现与 `noshard` / `groupshard` 形态解析能力；
   - 配套由智能体 O 撰写的 **《TEST-ZooKeeper真实环境测试手册.md》**，支持内网全自动化集成测试。

4. **数据治理与慢 SQL 深度扫描 (V1.5.2.x)**：
   - 支持集群级慢 SQL 数据源 `monitordb` (15001/tdsqlpcloud_monitor) 抓取、多 SET 聚合与 10 列增强诊断；
   - 支持日常巡检多日趋势看板与交互式 HTML 深度比对报告（含 CSP 非干扰与原生 JS 程序化事件绑定）。

## 二、 核心重点：元数据库（System Meta-Database）变更与自动迁移详解

**在从 V1.2.0.9 升级至 V1.5.2.5 过程中，后台服务在启动时会自动安全地应用幂等 DDL 迁移（`ensure_db()` / `_migrate_old_tables()`），无需手动人工执行复杂 SQL 脚本。**

但为了内网智能体与 DBA 准确掌握元数据库变动，特将表结构变更列举如下：

### 1. 新增的 12 张核心系统表 (从 15 张扩展至 27 张)
- **`roles` / `role_permissions`**：基于 PBKDF2 和 RBAC 的角色与细粒度菜单/接口权限矩阵；
- **`rule_sets` / `rule_set_items`**：全局评估规则集基线与全网尺度管理；
- **`scan_schedules`**：慢 SQL 定时自动扫描计划；
- **`retention_policies`**：审计日志与慢 SQL 记录的数据保留与自动清理策略；
- **`schedule_leases`**：多节点分布式部署时的调度器租约锁；
- **`gate_rules` / `gate_audit_logs`**：实例级质量门禁策略与拦截审计日志；
- **`daily_inspection`**：集群/实例日常巡检指标多日走势与物理主机体检数据。

### 2. 存量关键表的增量字段（Incremental Columns）与扩容
- **`users` 表**：
  - 新增 `token_version` (INT DEFAULT 0)：会话及时吊销机制，改密或登出时秒级失效旧令牌。
- **`tdsql_connections` 表**：
  - 新增 monitordb 凭据字段：`monitor_host` (VARCHAR 128), `monitor_port` (INT), `monitor_user` (VARCHAR 128), `monitor_password_encrypted` (TEXT), `monitor_db` (VARCHAR 128)；
  - 新增 Proxy 多 SET 支持：`set_list` (VARCHAR 512)；
  - 新增多源判定与 ZK 发现字段：`detected_instance_type`, `instance_type_detected_at`, `instance_type_probe_error`, `zk_instance_kind`, `zk_instance_id`, `zk_synced_at`, `instance_type_locked`, `instance_type_locked_value`。
- **`slow_queries` 表**：
  - 扩容 `set_id`：从 VARCHAR(32) 升级扩容至 VARCHAR(512)，满足多 SET 聚合场景；
  - 扩容 `client_user` 和 `client_host`：类型升级为 `TEXT`；
  - 新增 DML 影响行数：`rows_affected` (BIGINT)；
  - 新增 10 列诊断增强：`explain_plan`, `explain_issues`, `involved_tables`, `table_stats`, `table_schema_ddl`, `index_details`, `redundant_indexes`, `stats_update_info`, `stats_expired`, `scan_efficiency`。
- **`audit_history` 表**：
  - 新增 `db_name` (VARCHAR 128)、`rule_set_id` (VARCHAR 64)、`instance_type` (VARCHAR 16)、`instance_type_source` (VARCHAR 16)、`skipped_rules_count` (INT)；
  - 新增联合索引：`idx_audit_conn (connection_id, created_at)`。
- **`operation_logs` 表**：
  - 新增滑动窗口索引：`idx_log_type_ip_time (operation_type, ip_address, created_at)`。

## 三、 内网升级与安装操作步骤

### 1. 部署包解压与预检
```bash
# 解压发布包
tar -zxvf tdsql-sqlcheck-v1.5.2.5-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.5.2.5

# 执行部署预检（要求全 PASS，重点确认第 7 节 backend.main 导入无异常）
bash deploy/preflight_check.sh
```

### 2. 配置文件校验 (`deploy/.env`)
检查并确认 `deploy/.env` 中的关键元数据库连接参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Admin@1234
```

### 3. 执行安装与一键服务重启
```bash
# 执行安装脚本（自动停止旧服务、升级包代码、初始化/迁移元数据库表结构）
bash deploy/install.sh

# 验证部署与健康检查（输出 version: 1.5.2.5）
bash deploy/verify_deploy.sh
```

## 四、 内网 ZooKeeper 真实环境专项实测（给内网智能体的执行指令）

部署完成后，内网智能体需按照包内附带的 **《docs/TEST-ZooKeeper真实环境测试手册.md》** 在内网环境完成 ZooKeeper 只读发现验证：

1. **测试文档位置**：`docs/TEST-ZooKeeper真实环境测试手册.md`
2. **测试要点**：
   - 校验 ZK 连通性与 `zkCli.sh` 权限（只读访问 `/tdsqlzk`）；
   - 调用 `POST /api/v1/tdsql/discover` 接口校验内网全量 TDSQL 实例与 `groupshard`/`noshard` 形态解析；
   - 确认实例注册后 `S2` 源 `zk_instance_kind` 成功回写落库；
   - 参照手册第 5 节输出标准 Markdown 测试结果报告。
