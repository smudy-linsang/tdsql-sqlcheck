## 一、 评估范围与版本特性总览

V1.6.0.0 是系统的重大版本升级，重点完成了以下核心功能与架构提升：

1. **「慢SQL治理 / 原始慢日志」独立子模块 (SSH Exporter V1)**：
   - 解决了现有 `monitordb`（仅有采集时刻）、`digest`（无历史窗口）、`processlist`（无历史记录）在逐条慢 SQL 追溯上的痛点；
   - 引入 CheckSQL 部署机经内网 SSH 只读拉取 Proxy/Gateway 日志块的采集链路；
   - 增加 `slow_log_sources`, `slow_log_source_nodes`, `slow_log_cursors`, `slow_log_events`, `slow_log_runs` 5 张 V7 数据库新表。
2. **统一 SQL 脱敏与 SHA-256 指纹服务 (`sql_masking.py`)**：
   - 规范了全局 SQL 模板化、字面量遮蔽、指纹计算与 8 KiB 超长展示截断机制。
3. **安全与受限采集架构**：
   - 远端使用 Go 编写静态受限导出器 (`raw_slowlog_exporter`)，基于 ForceCommand 与白名单路径隔离；
   - 强制 OpenSSH 严格主机指纹校验与 Secret 引用，严禁口令与 root 访问。

## 三、 缺陷清单与展图施工修复方案（供智能体 O 修复）

本轮测试共发现 3 项 **P3 级轻微缺陷**（测试代码与重构后业务语义不匹配导致的断言失败），无 P0/P1/P2 级阻碍性缺陷。详细描述与可展图施工的修复方案如下：

### 缺陷 1 (Defect-01): `test_monitordb_time_window.py` 表单提示 `v-if` 断言失败
- **缺陷级别**：P3 (低 - 仅测试断言遗留)
- **复现位置**：`tests/test_monitordb_time_window.py` Line 216 (`test_time_window_has_per_source_note`)
- **根因分析**：PR #25/PR #27 对 `frontend/index.html` 慢 SQL 采集抽屉模板进行了精简重构，将原有的 `v-if="scanTaskForm.source==='monitordb'"` 条件块合并优化为统一提示样式，导致测试脚本中对此字符串的硬编码正则匹配返回 `None`。
- **展图施工方案 (Agent O 执行)**：
  更新 [`tests/test_monitordb_time_window.py`](file:///c:/TDSQL_SQLCHECK/TDSQL-SQLCheck/tests/test_monitordb_time_window.py) 第 216 行断言，检查表单提示包含 `form-note` 和 `采集时间` 即可：
  ```python
  # 修改前:
  assert re.search(r"v-if=\"scanTaskForm\.source==='monitordb'\"", note)

  # 修改后 (适应最新 index.html 结构):
  assert "form-note" in note and "采集时间" in note
  ```

---

### 缺陷 2 (Defect-02): `test_monitordb_time_window.py` 提示框关键字断言失败
- **缺陷级别**：P3 (低 - 仅测试断言遗留)
- **复现位置**：`tests/test_monitordb_time_window.py` Line 230 (`test_time_window_tooltip_covers_all_three_sources`)
- **根因分析**：`frontend/index.html` 中的 Tooltip 帮助提示进行了汉化与语义明确，把 HTML 中的英文关键字 `digest` 替换为了中文 `性能摘要`。测试脚本仍要求文本中包含 `"digest"` 字符串，导致断言失败。
- **展图施工方案 (Agent O 执行)**：
  修改 [`tests/test_monitordb_time_window.py`](file:///c:/TDSQL_SQLCHECK/TDSQL-SQLCheck/tests/test_monitordb_time_window.py) 第 230 行的关键字元组：
  ```python
  # 修改前:
  for kw in ("monitordb", "digest", "processlist", ...):

  # 修改后 (同时兼容中文与英文描述):
  for kw in ("monitordb", "性能摘要", "processlist", ...):
      assert kw in tip, f"tooltip 缺少关键说明: {kw}"
  ```

---

### 缺陷 3 (Defect-03): `test_smoke_multi_set.py` 仍断言 Digest 缺失时间窗返回 HTTP 422
- **缺陷级别**：P3 (低 - 仅测试断言遗留)
- **复现位置**：`tests/test_smoke_multi_set.py` Line 511 (`test_fetch_digest_requires_time_window`)
- **根因分析**：PR #27 (`fix: clarify digest snapshot time semantics`) 已将 Proxy 层 Digest 慢 SQL 的接口行为重构为“返回当前集群累计快照”，不再强制校验 `time_from`/`time_to` 并返回 HTTP 422，而是直接响应 HTTP 200 OK 及其快照内容。但旧测试脚本 `test_smoke_multi_set.py` 仍遗留了 `assert resp.status_code == 422`。
- **展图施工方案 (Agent O 执行)**：
  更新 [`tests/test_smoke_multi_set.py`](file:///c:/TDSQL_SQLCHECK/TDSQL-SQLCheck/tests/test_smoke_multi_set.py) Line 511，将其断言改为 200 并重命名测试函数说明：
  ```python
  # 修改前:
  def test_fetch_digest_requires_time_window(self, client):
      resp = client.post("/api/v1/tdsql/slow-queries/fetch", json={"source": "digest", "limit": 10, "min_time": 0.1})
      assert resp.status_code == 422

  # 修改后 (契合 V1.5.2.5+ 快照语义):
  def test_fetch_digest_returns_snapshot_without_time_window(self, client):
      resp = client.post("/api/v1/tdsql/slow-queries/fetch", json={"source": "digest", "limit": 10, "min_time": 0.1})
      assert resp.status_code == 200
  ```

## 四、 真实环境投产准入门禁要求

为确保 V1.6.0.0 原始慢日志模块在内网生产环境安全运行，投产前必须满足以下门禁：
1. **只读账号与受限 Export**：目标 Proxy/Gateway 主机必须配置专用的 `tdsql_log_reader` 只读账号，并使用 `ForceCommand` 限制为可执行 `raw_slowlog_exporter`。
2. **凭据隔离**：SSH 密钥和 known_hosts 指纹文件需置于部署机受控目录，严禁硬编码或入库。
3. **格式探查校验**：添加新采集源后需先调用 Probe 验证导出器版本（1.x）及慢日志格式签名。
