## 一、 智能体 O 设计方案与实施内容学习

智能体 O 在 `docs/DESIGN-v1.6.0.1-ZK自动发现连接标准化导入详细设计说明书_智能体O.md` 中提出的改进设计，彻底解决了此前“发现结果仅为 ZK 记录直译、无法直接用于生产审核”的痛点。核心改动包括：

1. **两阶段交互设计 (Two-stage Discovery & Import)**：
   - **阶段一 (只读 ZK 探查)**：仅读取 `/tdsqlzk` 及子节点，解析 `groupshard` (分布式) 与 `noshard` (集中式) 拓扑，获取 Proxy 主机与 SET 列表，**严禁在前端或日志回显 ZK `setrun` 中的敏感口令**。
   - **阶段二 (数据库探查与预检)**：结合操作者输入的业务账号与 MonitorDB 信息，经 Proxy 执行 `SHOW DATABASES` 探查真实业务库，从 MonitorDB 查取真实业务实例名称。
2. **一库一连接规范化命名 (Standardized Connection Naming)**：
   - 连接命名公式：`${instance_name}-${proxy_port}-${database}`；
   - 彻底废弃以往将默认库填为 `ALL` 的伪连接模式，实现精细化单库接入。
3. **安全关断与异常降级 (Fail-Closed & Secure)**：
   - 当 ZK 无法建立完整会话或鉴权失败时，严格报 HTTP 503 错误并记录诊断日志，坚决不回退伪造 Mock 数据。
