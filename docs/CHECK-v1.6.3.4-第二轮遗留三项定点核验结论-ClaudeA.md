## 1. 三项定点核验

### P2-04 闭集白名单 —— ✅ 通过，且实现细节比我给的更到位

* **§5.2.1 已建立 36 项闭集 `R043_NON_TARGET_HEADS`。**我用脚本把设计正文的集合与我上一轮建议的集合做了差集比对：**36 项完全一致，无多无少，且不含 `UPDATE`/`DELETE`**。
* **自相矛盾的两句已消除。**全文检索 `CREATE/ALTER/INSERT/SELECT 等`、`不硬猜 NOT_APPLICABLE` —— **0 命中**，开放式枚举与结尾禁令都已删除。
* **DML-18 比我的版本更严，并堵上了我留的一个漏洞。**我原文只要求"E999 总数改后 ≤ 改前"，这个聚合口径可以被"删掉别处一条错误来抵消新增一条误报"钻空子。设计写成：

  > 每条原无 E999 的不得新增 E999，**总条数改后不大于改前**；原 parse_error/KFN/E999 不被清除，其余非 R043 规则命中/级别逐条一致

  逐句锁 + 聚合锁双重，我的漏洞被 O 补上了。

* **DML-19 是 O 新加的，我上一轮没写，属于实打实的增量。**我只写了"取顶层首个有效 token"，没说怎么取。O 指出锁定版词法器有两个坑，我实测确认**全部属实**：

  | 输入 | 首 token 类型 | 首 token 文本 | 陷阱 |
  |---|---|---|---|
  | `LOCK TABLES t WRITE` | `COMMAND` | **`'LOCK TABLES'`** | 整串两个词，比 `token.text == "LOCK"` 必然失败 |
  | `UNLOCK TABLES` | `COMMAND` | `'UNLOCK TABLES'` | 同上 |
  | `'SELECT' AS x` | `STRING` | `'SELECT'` | 字符串字面量可冒充语句头 |
  | `` `SELECT` FROM t `` | `IDENTIFIER` | `'SELECT'` | 反引号标识符可冒充语句头 |

  更关键的是 O 点名的那句"原 `_lex_head_words` 丢弃了 token 类型，不能直接全信"。我查了 `parser_legacy.py:185`：

  ```python
  return [t.text.upper() for t in toks][:limit]
  ```

  **确实只留文本、丢掉类型**。实施者若图省事复用这个现成函数，上表后两行的伪造头会被当成真头。这个坑我上一轮没看到，O 看到了。

### P2-05 容量与顺序 —— ✅ 通过，两处不照搬我也认可

* **§4.3 第 5 条已改为四层调度**：`C1 旧分片 S → C2 only_base → C3 仅独立目录可见 → C4 剩余单表/广播`，层内精确名稳定排序，**全实例 C1→C2→C3→C4**（不是按库扫完四层再下一库），并明写"四层互斥且并集必须等于 C""只改变顺序，绝不改变 C、计数公式、unknown/unchecked 或 COMPLETE 条件"。PAR-19/20 配套。
* **O 拒绝照搬我的两处论证，两处他都对**：
  1. 我写"旧分片先验命中概率最高、下界尽可能接近真值"。O 指出这是**没有实测支撑的概率断言**——若某环境的现代主表大多落在旧单表结果里，先扫旧分片未必更优。设计改成只承诺"确定性顺序、不漏记候选"。我接受：这是我把启发式说成了模型。
  2. 我建议用 `information_schema` 基表 `COUNT(*)` 估 `|C|` 上界。O 指出它既可能含物理子表、又未必覆盖 Proxy 独有对象。我复核了代码：`raw_base` 正是 information_schema 口径、要经 `_classify_subpartitions` 才剔除物理子表；而 reconciliation 里本就存在 `only_proxy`（Proxy 有、基线无）。**所以 COUNT 既不是上界也不是下界，我这条建议是错的。**设计改用同范围三集合实测并集，并只在三源齐全时使用 `max(|L|,|P|,|B|) <= |C| <= |L|+|P|+|B|`——集合论上成立。
* **§8.2.1 容量核算已落文**，含执行责任分工、六步只读流程、记录模板。我复算了其中的量纲算例：`T_plan = 30+10+5+2000×0.05 = 145` 秒、`30+10+5+2000×0.10 = 245` 秒、`T_remaining = 180−45 = 135`，`135/0.10 = 1350` 张——**四处算术全部正确**，且文中明确标注"纯算例，不是内网实测"。
* **180 秒按裁定保持不变**，PAR-20 专门锁住"共享 deadline 不重置、不额外加 300 秒"。

### P3-04 固定并发 —— ✅ 通过

配置表该行已改为 `固定常量 1（非调优项）`；§6.7 增加"不可调项发布检查"，要求配置清单/运维说明/capabilities 三处同标"固定、不可调"，并要求**切生产前**用拟发布配置跑启动校验（而不是停服后才发现起不来）；GW-C4 补了对应断言。
