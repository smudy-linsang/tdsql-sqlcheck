## 一、 版本核心变更与修复说明 (V1.6.1.6 ➔ V1.6.1.7)

从 V1.6.1.6 推进升级至 V1.6.1.7，系统进行了针对性的交互健壮性修复：

1. **“从 ZK 自动发现”实例列表跨五维筛选与跨分页勾选持久化修复**：
   - **问题现象**：在 ZK 自动发现扫描出实例后，若用户先通过端口（或名称、业务库、Proxy、形态）筛选并选中第 1 个实例，然后再切换或清空筛选条件选择第 2 个实例时，先前选中的实例勾选会被意外清空重置。
   - **根因分析**：V1.6.0.3 引入五维筛选和分页表格时，前端 `<el-table>` 缺少 `row-key="item_token"` 与 `reserve-selection` 属性，且使用了手写的差集计算逻辑；在用户切换/退格清空筛选框时，表格触发重渲染并抛出空选择事件，导致计算属性切片竞态丢失了已选中的历史记录。
   - **修复方案**：
     - 在 [`frontend/index.html`](file:///c:/TDSQL_SQLCHECK/TDSQL-SQLCheck/frontend/index.html) 的 ZK 发现表格 `<el-table>` 上声明 `row-key="item_token"`，在多选列声明 `reserve-selection`；
     - 在 [`frontend/static/js/app.js`](file:///c:/TDSQL_SQLCHECK/TDSQL-SQLCheck/frontend/static/js/app.js) 中将选中处理逻辑简化为 Element Plus 原生托管标准：`zkSelected.value = val || [];`；
     - 彻底实现用户在多轮端口筛选、实例名模糊搜索、形态切换以及跨分页翻页过程中，**所有选中的实例全局持久记忆**，回显状态 100% 正确。

2. **零副作用保证**：
   - 本次更新仅涉及前端展示层与版本标识配置，**无任何数据库 DDL 变更、无任何后端 API 接口改动、无新增第三方依赖**；
   - 支持通过极小体积的增量补丁包（`patch`）秒级平滑热替换生效。

## 三、 内网智能体增量打补丁部署操作步骤（推荐方式）

### 1. 拷贝与解压增量补丁包
在当前系统安装目录（例如 `/data/tdsql-sqlcheck` 或 `/opt/tdsql-sqlcheck`）同级或临时目录下：
```bash
# 解压增量补丁包
tar -zxvf tdsql-sqlcheck-v1.6.1.7-patch.tar.gz
cd tdsql-sqlcheck-v1.6.1.7-patch
```

### 2. 执行一键应用补丁脚本
```bash
# 自动备份原文件、覆盖更新、并平滑重启服务
sudo ./apply_patch.sh /path/to/tdsql-sqlcheck
# 注：若当前直接在系统运行目录下解压，直接执行 sudo ./apply_patch.sh 即可
```

`apply_patch.sh` 执行流程：
1. 校验目标安装目录的有效性；
2. 在 `backup_v1.6.1.6_<timestamp>/` 下自动备份受影响的文件（`index.html`, `app.js`, `config.py`, `VERSION`）；
3. 复制增量补丁文件到目标工程；
4. 平滑重启 `tdsql-sqlcheck` 守护进程（或 `systemctl restart tdsql-sqlcheck`）；
5. 调用 `/health` 探针校验服务状态与 `1.6.1.7` 版本号。

## 四、 升级后验证指南

1. **服务健康与版本验证**：
   ```bash
   curl -s http://127.0.0.1:8000/health
   # 预期输出: {"status":"ok","version":"1.6.1.7"}
   ```

2. **ZK 发现多维筛选勾选验证**：
   - 浏览器强刷新页面（`Ctrl + F5`）；
   - 进入“平台治理” ➔ “实例管理” ➔ “从ZK自动发现” ➔ 点击“开始扫描”；
   - 在“端口”筛选框输入端口 A（例如 `15001`），勾选筛选出来的第 1 个实例；
   - 清空端口框并输入端口 B（例如 `15002`），勾选筛选出来的第 2 个实例；
   - 点击“配置导入并生成预览”，下方统计汇总准确显示 `已选择 2 个实例`，且生成的预览中包含两次筛选选中的全部实例！
