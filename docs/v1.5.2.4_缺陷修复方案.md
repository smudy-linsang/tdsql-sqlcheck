### 0.1 对 A 报告的三点修正/补充（不影响其结论成立）

1. **P0-01 的表现随 Python 版本不同**。生产发布包 wheels 全部为 cp311（Python 3.11），
   注解在导入期立即求值 → `NameError`，**进程起不来**，与 A 实测一致。
   但本地开发机是 Python 3.14（PEP 649 注解惰性求值），`import backend.main` 反而成功——
   接口静默退化：`request` 参数被 FastAPI 降级为**必填查询参数**，实测
   `PUT /slow-queries/1/status` 带 JSON body 返回
   `422 {"loc":["query","request"]}`。**这解释了为什么开发环境 11 个提交都没人发现**：
   开发机上服务是能起的，只是这一个接口坏了。两种表现都必须修，修法相同。
2. **P1-02 实际缺 6 列而非 5 列**（新发现，编号 P1-02b）：`scan_snapshots.rule_set_id`。
   该表**只由** `backend/schema/v2/020_scan_compare_tables.sql` 创建（`database.py::_create_all_tables`
   不建它），而 `migrator.run_migrations()` 在 `init_db()` 里排在 `_migrate_old_tables` **之后**（L386）。
   所以首次启动时 `_migrate_old_tables` 执行时 `scan_snapshots` 尚不存在，L576-578 的
   `rule_set_id` 补列被守卫跳过；表随后才由 migrator 建出（v2 脚本 DDL 里没有 rule_set_id；
   v4 脚本补的是 `instance_type`，不含 rule_set_id）。第二次启动自愈。
   **注意：这一列连"从 1.2.0.9 升级"的路径也踩**——1.2.0.9 没有 scan_snapshots 表，
   升级后的首次启动同样走"表不存在→跳过补列"的路径。A 说"升级路径不受影响"只对他那 5 列成立。
   A 的对比没抓到它，是因为他的升级库与全新库**都缺**这一列，diff 抵消了。
3. **A 给 P1-02 的修复建议第 2 条选错了文件**。A 建议把 5 列补进
   `backend/schema/v0/001_init_tables.sql`——但该文件是遗留最小脚本，只含
   `schema_version` 和一个旧版 `users`（username 主键，与现行结构不同），
   **根本不含 audit_history / gate_audit_logs**。真正的建表 DDL 在
   `backend/services/database.py::_create_all_tables`。且 v0 脚本受 migrator checksum
   跟踪，无谓修改只会制造 checksum 漂移告警。本方案改 `database.py` 的 DDL，不动任何 schema 脚本。

另：远程已存在分支 `origin/fix/pressure-test-credential-env`（`8648b11`），
是 P2-05 的**部分**修复（两个实例口令改环境变量 + 缺失时 fail-fast）。本方案在其基础上补全，见 FIX-5。

## 3. FIX-2（P1-02 / P1-02b）全新安装 6 列缺失

### 3.2 改动一：调整 `init_db()` 执行顺序

**位置**：L358-393 的 `init_db()`。

**现状**（顺序错误）：

```
schema_version 建表
_migrate_old_tables(conn)      ← L372 先补列（全新库无表可补，整体空转）
_create_all_tables(conn)       ← L375 后建表
```

**改为**（建表 → 脚本迁移 → 补列 → 默认数据）：

```python
        # 创建所有表（IF NOT EXISTS确保幂等）
        _create_all_tables(conn)

        # v1.2 增量 Schema 迁移文件加载。
        # 必须先于 _migrate_old_tables：scan_snapshots 等表只由 v2+ 脚本创建，
        # 若补列先跑，这些表的增量列（如 rule_set_id）在首次启动会被守卫跳过。
        try:
            from backend.schema.migrator import migrator
            migrator.run_migrations()
        except Exception as me:
            logger.warning(f"Schema 增量迁移执行提示: {me}")

        # 旧版表增量补列：必须在建表与脚本迁移之后。
        # v1.5.2.4 P1-02：原先放在建表之前，全新安装时 table_names 快照为空，
        # 所有 `if "<表>" in table_names` 守卫为假，6 列被整体跳过，
        # 首次登录改密即 500（Unknown column 'token_version'）。
        _migrate_old_tables(conn)

        # 初始化默认数据
        _init_default_data(conn)

        conn.commit()
        logger.info("数据库初始化完成 (V2.0, MySQL)")
```

即：把原 L371-372 的 `_migrate_old_tables` 调用移动到 migrator 之后；

## 4. FIX-3（P2-03）R043 多表 UPDATE 判定正则

### 4.1 改动文件
`backend/engine/parser/parser_legacy.py` + `tests/test_sit_v1_rules.py`

### 4.2 施工步骤

**位置**：L250-257。现状：

```python
        # 检测联表更新 / 联表删除
        clean_sql_no_comm = re.sub(r'--[^\n]*', '', sql_lower)
        clean_sql_no_comm = re.sub(r'/\*.*?\*/', '', clean_sql_no_comm, flags=re.DOTALL).strip()
        if re.search(r"\bupdate\s+.*?\bjoin\b", clean_sql_no_comm, re.DOTALL) or \
           re.search(r"\bupdate\s+[^set]+,", clean_sql_no_comm, re.DOTALL) or \
           re.search(r"\bdelete\s+.*?\bjoin\b", clean_sql_no_comm, re.DOTALL) or \
           re.search(r"\bdelete\s+[a-zA-Z0-9_`\s,]+from\b", clean_sql_no_comm, re.DOTALL):
            parsed.is_multi_table_update = True
```

**整段替换为**（UPDATE 的两个分支合并为"目标表段"判定；DELETE 两分支原样保留）：

```python
        # 检测联表更新 / 联表删除
        clean_sql_no_comm = re.sub(r'--[^\n]*', '', sql_lower)
        clean_sql_no_comm = re.sub(r'/\*.*?\*/', '', clean_sql_no_comm, flags=re.DOTALL).strip()
        # UPDATE：取 UPDATE 与 SET 之间的目标表段，段内含逗号或 JOIN 即联表。
        # 旧写法 [^set]+ 是否定"字符"组（排除字母 s/e/t），并非排除单词 SET——
        # 对 t_xxx 等含 s/e/t 的表名恒不匹配，导致逗号式联表 UPDATE 静默漏报（P2-03）。
        # 同时旧 JOIN 分支会把 SET 子句里子查询的 JOIN 误判进来，限定目标段后一并修正。
        m_upd = re.search(r"\bupdate\b(.*?)\bset\b", clean_sql_no_comm, re.DOTALL)
        upd_multi = bool(m_upd and ("," in m_upd.group(1)
                                    or re.search(r"\bjoin\b", m_upd.group(1))))
        if upd_multi or \
           re.search(r"\bdelete\s+.*?\bjoin\b", clean_sql_no_comm, re.DOTALL) or \
           re.search(r"\bdelete\s+[a-zA-Z0-9_`\s,]+from\b", clean_sql_no_comm, re.DOTALL):
            parsed.is_multi_table_update = True
```

判据说明（施工时不必重推，列在此备档）：
- `\bset\b` 不会命中 `offset` / `set_config` 等含 set 的标识符（词边界两侧都要求非单词字符）。
- 目标段止于**第一个** `SET` 关键字，故 SET 值、WHERE 子句里的逗号不进入判定。
- `UPDATE a JOIN b ON ... SET`：JOIN 位于 UPDATE 与 SET 之间 → 命中，与旧 JOIN 分支行为一致。

### 4.3 必须补的用例（规约 R-12 反向鉴别）

在 `tests/test_sit_v1_rules.py` 的 `TestNewDMLAndSecurityRules` 类内、
`test_r043_multi_table_update` 之后追加（断言写法参照同文件既有用例的取 `rule_ids` 方式）：

```python
    def test_r043_comma_style_with_t_prefix(self):
```

```python
            if re.match(r'^--\s*SQL\s+Object\s*:', stripped_line, re.IGNORECASE) \
                    and not in_begin_block:
                pending = "".join(current_stmt).strip()
                cleaned_pending = re.sub(r'--[^\n]*', '', pending)
                cleaned_pending = re.sub(r'/\*.*?\*/', '', cleaned_pending,
                                         flags=re.DOTALL).strip()
                if cleaned_pending:   # 仅当积累了真实代码才断开；纯注释归属下一条
                    statements.append((pending, stmt_start_line))
                    current_stmt = []
                    stmt_start_line = line_no
```

设计要点（备档）：
- 标记行本身**落入新块**（flush 后继续走 `current_stmt.append(l)`），
  与正常路径"紧邻注释归属下一条语句"的行为一致。
- flush 出的残块按原文入列（与 L393-398 的尾部 flush 行为一致，不做横幅裁剪）。
- `not in_begin_block` 防止存储过程体内出现同名注释时误断。
- 非本系统抽取的普通 SQL 文件不含该标记，行为完全不变。

```python
# -*- coding: utf-8 -*-
"""路由完整性守卫（R-17）

背景：v1.5.2.4 P0-01，a1fdc53 误删 StatusUpdateRequest。
Python 3.11 下 backend.main 导入期 NameError（进程起不来）；
Python 3.14 下（PEP 649 惰性注解）导入成功，但 FastAPI 把该请求体参数
静默降级为必填查询参数——两种形态都必须在提交前被本文件拦截。
"""
from fastapi.routing import APIRoute

from backend.main import app


def _routes():
    return [r for r in app.routes if isinstance(r, APIRoute)]


def test_slow_query_status_route_consumes_json_body():
    """P0-01 定点回归：状态更新接口必须以 JSON 请求体接收参数"""
    route = next(r for r in _routes()
                 if r.path == "/api/v1/slow-queries/{slow_id}/status")
    assert route.body_field is not None, \
        "StatusUpdateRequest 缺失时该接口会退化为查询参数，见 docs/v1.5.2.4_缺陷修复方案.md FIX-1"


def test_no_route_query_param_named_request():
    """通用守卫：请求模型类被误删时，FastAPI 会把形参 request 降级为查询参数。
    正常代码里不存在名为 request 的查询参数（fastapi.Request 不算查询参数），
    出现即说明某个 BaseModel 引用失效。"""
    offenders = []
    for r in _routes():
        for p in r.dependant.query_params:
            if p.name in ("request", "req", "body", "payload"):
                offenders.append(f"{r.path} -> {p.name}")
    assert not offenders, f"疑似请求模型缺失导致的参数退化: {offenders}"
```
