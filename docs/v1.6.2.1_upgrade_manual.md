# TDSQL-SQLCheck V1.6.2.1 综合升级操作手册

| 项目 | 内容 |
|---|---|
| **目标版本** | **v1.6.2.1** |
| **发布日期** | 2026-08-22 |
| **内网基线版本** | **v1.6.1.9**（亦兼容 v1.6.1.6 / v1.6.1.7 / v1.6.1.8 / v1.6.2.0） |
| **核心修复** | 1. **R061 索引命名误报根治**：剥离反引号消除 78.6% 系统性假告警，保留 DDL 原始大小写<br>2. **TDSQL 方言解析降级根治**：修复 `TDSQL_DISTRIBUTED BY HASH/RANGE/LIST` 及 `BROADCAST` 导致整表静默漏审与虚假“通过”问题 |
| **升级模式** | **模式 A：全量包升级（推荐）** / **模式 B：增量热补丁（针对 v1.6.1.9 极速热更）** |

## 一、 升级方式选型

### 模式 A：全量发布包升级（推荐）
- **介质**：`tdsql-sqlcheck-v1.6.2.1-linux-x86_64.tar.gz`
- **特点**：标准版本发布目录（`releases/v1.6.2.1`），具备完整的 wheels 离线依赖、自动继承加密密钥（`TDSQL_ENCRYPTION_KEY`），支持一键无损回滚。
- **耗时**：约 1~2 分钟。

### 模式 B：增量热补丁包升级（针对 v1.6.1.9 在线极速修复）
- **介质**：`tdsql-sqlcheck-v1.6.2.1-patch.tar.gz`
- **特点**：仅包含最小变动文件（解析器、R061 规则、前端入口与说明文档），自动执行变动前备份并秒级完成热覆盖与进程平滑重启。
- **耗时**：约 5~10 秒。

---

## 二、 模式 A：全量发布包升级步骤

### 1. 上传介质与校验
将发布包上传至服务器 `/tmp` 目录并校验完整性：
```bash
cd /tmp
sha256sum -c tdsql-sqlcheck-v1.6.2.1-linux-x86_64.tar.gz.sha256
# 应输出: tdsql-sqlcheck-v1.6.2.1-linux-x86_64.tar.gz: OK
```

### 2. 解压与安装
```bash
tar -zxvf tdsql-sqlcheck-v1.6.2.1-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.2.1
sudo ./deploy/install.sh --install-dir /opt/tdsql-sqlcheck
```
> **注**：`install.sh` 脚本已内置防呆机制：跨版本升级时会自动从历史版本继承并固化 `TDSQL_ENCRYPTION_KEY` 与 `data/encryption.key`，确保已保存的数据库实例密码 100% 正常解密。

### 3. 健康检查与验证
```bash
sudo /opt/tdsql-sqlcheck/current/deploy/verify_deploy.sh
```

## 三、 模式 B：增量补丁升级步骤（从 v1.6.1.9 升级）

### 1. 上传并解压补丁
```bash
cd /tmp
tar -zxvf tdsql-sqlcheck-v1.6.2.1-patch.tar.gz
cd tdsql-sqlcheck-v1.6.2.1-patch
```

### 2. 执行一键补丁应用
```bash
# 传入当前实际运行目录，例如 /opt/tdsql-sqlcheck/current
sudo ./apply_patch.sh /opt/tdsql-sqlcheck/current
```
该脚本将自动完成：
1. 自动备份当前受影响文件至 `backup_pre_v1.6.2.1_<时间戳>` 目录；
2. 覆盖 `backend/engine/rules/index.py`、`backend/engine/parser/parser_legacy.py`、`backend/config.py`、`VERSION`、`frontend/index.html` 等变动文件；
3. 平滑重启 `tdsql-sqlcheck` 后台服务并校验服务状态。

## 四、 升级后功能验证与业务表现确认

### 1. 业务指标预期变动说明
1. **R061 误报大幅下降**：
   - 包含 `` `idx_xxx` `` 反引号索引的表不再报出违规；
   - 告警总数将出现合理回落（在标准 14 表场景下违规条目由 43 条降为 32 条，下降 25.6%）。
2. **HASH 与广播表恢复全面审核**：
   - 使用 `TDSQL_DISTRIBUTED BY HASH(...)` 的分片表将正常报出时间戳（R036）、逻辑删除（R037）等真实违规，不再出现虚假“通过”。

### 2. 验证步骤
1. **浏览器刷新**：访问 `http://<IP>:8000`，确认页面标题与登录页版本号显示为 `V1.6.2.1`。
2. **在线审核复测**：
   - 输入包含反引号索引的 DDL（如 `` KEY `idx_user` (`user_id`) ``），验证不再触发 R061 误报。
   - 输入包含非 idx 前缀索引的 DDL（如 `` KEY `cus_IDX1` (`cust_no`) ``），验证准确触发 R061 且提示信息保留 `cus_IDX1` 原生大小写。

## 五、 回滚方案

### 模式 A 回滚（全量包升级回滚）
```bash
# 回切到上一个版本目录
PREV_DIR=$(cat /opt/tdsql-sqlcheck/.previous_release)
sudo ln -sfn "$PREV_DIR" /opt/tdsql-sqlcheck/current
sudo systemctl restart tdsql-sqlcheck
```

### 模式 B 回滚（增量补丁回滚）
```bash
# 从备份目录还原文件
cd /opt/tdsql-sqlcheck/current
BACKUP_DIR=$(ls -td backup_pre_v1.6.2.1_* | head -n 1)
sudo cp -r "$BACKUP_DIR/"* ./
sudo systemctl restart tdsql-sqlcheck
```
