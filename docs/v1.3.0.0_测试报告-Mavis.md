## 9. 4 项问题详细说明

### BUG-130-01 (P1): 缺 module 返回 422 而非 400 (E4006)

**测试用例**:
```
GET /api/v1/scan-compare/snapshots
→ 期望: 400 {"detail": "不支持的模块类型", "code": "E4006"}
→ 实际: 422 {"detail": [{"type": "missing", "loc": ["query", "module"], "msg": "Field required", "input": null}]}
```

**根因** (`backend/api/scan_compare.py:98-100`):
```python
@router.get("/snapshots", summary="扫描快照列表（按实例/库名/时间筛选）")
def list_snapshots(request: Request, module: str, connection_id: str = "",  # ← module 必填
                   db_name: str = "", date_from: str = "", date_to: str = "",
                   limit: int = 20, offset: int = 0):
    _check_module_perm(request, module)  # ← module="" 时 _check_module_perm 不报错
```

FastAPI 在 endpoint 函数执行**之前**就做 Pydantic 校验, 必填参数 `module` 缺失直接 422, 不会进入 endpoint 函数。

**影响**:
- 客户端按设计文档约定的 `code` 字段无法获取错误码 (422 响应是 FastAPI Pydantic 格式,不是 A 自定义的 `{detail, code}`)
- 与设计文档错误码体系 (E4001-E4006 + E4031) 不一致
- 既有错误处理逻辑 (按 code 字段判断) 会失败

**建议修复** (供 A 参考):
```python
# 改为可选, 端点内手动校验
@router.get("/snapshots", summary="扫描快照列表")
def list_snapshots(request: Request, module: str = "",  # ← 默认空串
                   connection_id: str = "", ...):
    if not module:
        raise _err("E4006", "缺少 module 参数")  # ← 触发 A 自定义错误码
```

### BUG-130-02 (P1): `/api/v1/audit/extracted-reports` 响应字段命名不一致

**测试用例**:
```
GET /api/v1/audit/extracted-reports?connection_id=adhoc&limit=10
→ 设计文档 (API-v1.3 §2.1): {"total": 5, "items": [...]}
→ A 实际实现: {"total": 9, "reports": [...]}  ← 字段名是 reports 不是 items
```

**根因** (`backend/api/sql_audit.py:339-342`):
```python
return {
    "total": total,
    "reports": report_list  # ← 字段名 reports
}
```

**影响**:
- 前端按 `items` 字段取值会拿到 `undefined`, 数据丢失
- 与设计文档不一致, 文档需要重写
- `/api/v1/scan-compare/snapshots` 用 `items` (✓), `/api/v1/audit/extracted-reports` 用 `reports` (❌), 同类接口字段名不统一

**建议修复** (供 A 参考):
```python
# sql_audit.py:339-342
return {
    "total": total,
    "items": report_list  # ← 统一为 items
}
```

### BUG-130-03 (次要): M 补充 1 [set 区分位] 未实现

**测试代码** (`backend/api/sql_audit.py:263`):
```python
_items, _obj_total = _extract(results, target_db, node="")  # ← node 写死 ""
```

**A 的设计注释** (`backend/services/snapshot_extractors/schema_audit.py:7`):
> "node 为 set 预留位，当前恒传 ''（F1 经代理审核逻辑 schema，端点内无 set 变量）"

**实际影响**:
- TDSQL 分布式架构下, 同一 connection_id 可能管理多个 set (节点)
- 同一张表在 set_1 和 set_2 各有一份, 元数据问题应**按 set 独立成项**
- 当前实现: 跨 set 同问题会被合并为同一问题, 若只在 set_1 修复, set_2 仍有, 会被误判为"未修复"
- 实际触发场景: 仅当目标实例有多个 set 且只修复部分 set 时才会暴露

**影响范围**: 单 set 实例无影响; 多 set 分布式实例的比对结果**可能失真**

**建议**:
- A 决策: 当前不实施 (理由: 端点无 set 变量), 需在升级说明与文档中**显式标注**: "v1.3.0.0 暂不支持跨 set 区分, 分布式实例比对结果按 connection_id 汇总"
- 或 v1.3.0.1 补: 在 `extract_and_audit` 端点获取 set 列表, 逐个 set 生成 snapshot

### BUG-130-04 (测试代码): 密码笔误

**根因**: `tests/test_sit_rules.py:14` 与 `tests/test_uat_rules.py:13` 的 `_get_auth_headers()` 密码硬编码为 `"Admin@123"` (应 `Admin@1234`)

**影响**: 27 个 rules 集成测试 401 失败

**建议修复** (供 A 参考):
```python
# 两个文件 line 14 / 13
resp = requests.post(f"{API_BASE}/auth/login", json={"username": "admin", "password": "Admin@1234"}, timeout=3)
```
