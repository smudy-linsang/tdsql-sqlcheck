## 一、 版本核心变更与架构升级总览 (V1.6.1.3 ➔ V1.6.1.5)

从 V1.6.1.3 推进升级至 V1.6.1.5，系统完成了以下四大核心功能改进与健全性治理：

1. **“新建用户”选择角色下拉框动态加载与自定义角色支持**：
   - 将“新建用户”对话框的角色选择下拉菜单（`<el-select>`）由固定的 4 个内置角色替换为遍历 `rolesList` 动态渲染；
   - 增加在“用户管理”页面加载与打开新建用户弹窗时自动拉取 `rolesList` 的联动逻辑，确保在未提前访问“角色管理”页面的情况下，自定义角色（如 `测试人员` / `testor`）也能即时呈现在选择框中；
   - 升级 `roleLabelFn` 渲染函数，优先匹配并正确呈现自定义角色的中文名称（`role_name`）。

2. **角色管理功能增强与角色 ID 手动录入兜底**：
   - 新建角色弹窗提供 `角色ID` 显式录入项，兼容留空自动补全生成，防止触发 Pydantic 422 校验报错；
   - 静态资源添加强刷新控制（`?v=20260807.6`）与新建角色按钮点击行内安全兜底。

3. **全量自动化测试与回归验证 100% 通过**：
   - 补充自定义角色用户创建、角色解析联动测试用例；
   - 全量回归测试套件 1262 PASS / 0 FAIL / 28 SKIP 完全通过。

4. **系统元数据库（System Meta-Database）完全继承与自动迁移**：
   - 完整继承 v7（原始慢日志）、v8（ZK配置）、v9（连接唯一约束 `uk_host_port_database`）、v10（扫描富集与留痕）增量 Schema 架构，服务启动时自动运行 `migrator.run_migrations()`，无需手动执行 DDL。

## 二、 核心重点：元数据库（System Meta-Database）变更与自动迁移详解

**在升级至 V1.6.1.5 过程中，后台服务启动时会自动安全地应用全套增量 Schema 迁移文件（包含 v7 原始慢日志、v8 ZK配置、v9 连接唯一约束、v10 扫描富集与留痕）以及 `migrator.run_migrations()`，无需运维人员手动执行 DDL 脚本。**

元数据库包含历史连续演进架构：
- **v7 架构**：5 张原始慢日志系统表（`slow_log_sources`, `slow_log_source_nodes`, `slow_log_cursors`, `slow_log_events`, `slow_log_runs`）；
- **v8 架构**：`zk_discovery_config` 表存储 ZK 节点配置、Proxy 映射规则、段替换与富集参数；
- **v9 架构**：`tdsql_connections` 增加 `(host, port, database)` 联合唯一索引 `uk_host_port_database`（修正去重判据，绝不按同名误删）；
- **v10 架构**：`zk_discovery_config` 增加扫描富集配置列（`octet_rules_json`, `enrich_enabled` 等），`zk_discovery_import_items` 增加 `name_source` / `databases_source` 留痕列。

## 三、 全量部署与安装操作步骤（内网运维智能体执行）

### 1. 解压全量发布包与部署预检
```bash
# 解压全量发布包
tar -zxvf tdsql-sqlcheck-v1.6.1.5-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.1.5

# 执行部署预检（要求全 PASS，验证依赖与环境健康）
bash deploy/preflight_check.sh
```

### 2. 配置文件校验 (`deploy/.env`)
核对并更新 `deploy/.env` 配置文件中的元数据库与网络参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Abcd1234
```

### 3. 执行全量安装与服务升级重启
```bash
# 执行安装脚本（停止已有服务、覆盖全量代码、重新安装 wheels 依赖、升级数据库 Schema）
sudo ./deploy/install.sh
```
> ⚠️ **重要提醒**：`kazoo` 为本版必配离线依赖。全量安装时**必须完整运行 `./deploy/install.sh`（或执行 `pip install --no-index --find-links wheels/ -r requirements.txt`）**，切勿仅手动替换代码目录。

### 4. 上线最后自检 (必做步骤)
```bash
# 在目标部署机上运行部署校验脚本
bash deploy/verify_deploy.sh
```
`verify_deploy.sh` 会自动检测 Uvicorn 进程、端口监听、版本比对（输出 `1.6.1.5`）与 `/health` 端点，全部输出 PASS 即代表升级成功。
