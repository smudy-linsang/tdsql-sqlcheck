## 一、 补丁核心修复内容 (V1.6.1.8 ➔ V1.6.1.9)

1. **分布式建表语法缺陷修复 (`backend/engine/rules/distributed.py`)**：
   - 解决 TDSQL 内核输出的 `TDSQL_DISTRIBUTED BY HASH(col)` 语法被 R077 误判为“单表”的问题。
   - 解决广播表 `shardkey=noshardkey_allset` 被 R077/R054 误当做字段名报错的问题。
   - 引入可信尾部锚定与 MySQL `-- ` 注释词法清洗，杜绝伪造绕过。
2. **在线元数据审核接口容错加固 (`backend/api/sql_audit.py`)**：
   - 捕获实例异常并规范为 HTTP 400 业务错误，消除 unhandled 500。
3. **版本号统一推进**：
   - 系统各模块、前端标题与资源缓存版本统一升级至 `V1.6.1.9`。

## 二、 增量补丁安装三步法

### 步骤 1: 上传补丁介质
将 `tdsql-sqlcheck-v1.6.1.9-patch.tar.gz` 上传至目标服务器任意目录（如 `/opt/tdsql-sqlcheck` 或 `/tmp`）。

### 步骤 2: 解压并执行应用脚本
```bash
tar -zxvf tdsql-sqlcheck-v1.6.1.9-patch.tar.gz
cd tdsql-sqlcheck-v1.6.1.9-patch

# 执行热补丁应用脚本（指定当前运行目录）
sudo ./apply_patch.sh /opt/tdsql-sqlcheck/current
```

*补丁脚本将自动执行以下操作：*
1. **自动前置备份**：将待覆盖文件备份至 `/opt/tdsql-sqlcheck/current/backup_pre_v1.6.1.9_YYYYMMDD_HHMMSS`；
2. **增量文件覆盖**：精准更新 1 个规则文件、若干 API 路由、版本文件及前端静态资源；
3. **平滑重启服务**：重启 systemd 服务 `tdsql-sqlcheck`；
4. **版本核验**：比对并确认当前系统版本已为 `1.6.1.9`。

### 步骤 3: 业务功能复验
1. 访问 Web 页面，刷新确认页面版本号已更新为 **V1.6.1.9**；
2. 执行“在线元数据审核”，确认原先误报的实例已全部正常通过审核。

## 三、 补丁回滚方法

若需回退补丁，直接使用自动生成的备份目录即可：
```bash
# 假设备份目录为 backup_pre_v1.6.1.9_20260822_090000
cp -r /opt/tdsql-sqlcheck/current/backup_pre_v1.6.1.9_*/backend /opt/tdsql-sqlcheck/current/
cp -r /opt/tdsql-sqlcheck/current/backup_pre_v1.6.1.9_*/frontend /opt/tdsql-sqlcheck/current/
cp /opt/tdsql-sqlcheck/current/backup_pre_v1.6.1.9_*/VERSION /opt/tdsql-sqlcheck/current/
sudo systemctl restart tdsql-sqlcheck
```
