## 一、 版本核心变更与架构升级总览 (V1.5.2.5 ➔ V1.6.0.2)

从 V1.5.2.5 全量升级至 V1.6.0.2，系统完成了以下四大核心架构升级与能力拓展：

1. **ZooKeeper 自动发现与标准化连接导入 (G10 特性)**：
   - 实现了将 ZK 发现实例（`group_*` / `set_*`）结合业务账号与 MonitorDB 探查结果，一库一连接精细化导入 `tdsql_connections` 表（格式：`${instance_name}-${proxy_port}-${database}`）；
   - 支持只读两阶段探查、防重复导入校验、错误隔离与 fail-closed 关断安全防护。

2. **系统元数据库 Schema 迁移升级 (v7 / v8 / v9 连续递进)**：
   - **v7 架构**：新增 5 张原始慢日志系统表（`slow_log_sources`, `slow_log_source_nodes`, `slow_log_cursors`, `slow_log_events`, `slow_log_runs`）；
   - **v8 架构**：新增 `zk_discovery_config` 表保存 ZK 服务节点、映射规则与探查配置；
   - **v9 架构**：针对 `tdsql_connections` 增加 `(host, port, database)` 联合唯一索引（清理存量重复冲突，防重复建模与并发冲突）。

3. **依赖库更新**：
   - 增加纯 Python 协议连接驱动 `kazoo>=2.10.0`，全量发布包 `wheels/` 已内置对应离线 `.whl` 文件。

4. **安全与稳定性强化**：
   - 拦截并标准化 `IMPORT_CONFLICT` 重复连接错误；
   - 慢 SQL 扫描防崩溃容错与真实 TDSQL 慢日志时间戳兼容解析。

## 二、 核心重点：元数据库（System Meta-Database）变更与自动迁移详解

**在升级至 V1.6.0.2 过程中，后台服务启动时会自动安全地应用增量 Schema 迁移文件（`backend/schema/v7/070_raw_slow_log_collection.sql`、`v8/080_zk_discovery_config.sql`、`v9/090_tdsql_connections_unique_index.sql`）以及 `migrator.run_migrations()`，无需运维人员手动执行 DDL 脚本。**

以下为元数据库变更清单：

### 1. 新增 5 张原始慢日志系统表 (v7 架构)
- `slow_log_sources`：原始慢日志采集源表；
- `slow_log_source_nodes`：采集源节点信息表；
- `slow_log_cursors`：节点字节偏移与文件唯一标识游标表；
- `slow_log_events`：逐条慢日志解析事件与脱敏 SQL 表；
- `slow_log_runs`：调度运行审计与错误追踪表。

### 2. 新增 ZooKeeper 自动发现配置表 (v8 架构)
- `zk_discovery_config`：存储 ZK 服务地址列表、根路径 (`/tdsqlzk`)、Proxy 映射规则、启用状态与配置时间。

### 3. 实例连接表唯一约束与索引升级 (v9 架构)
- **`tdsql_connections` 表优化**：
  - 自动清理历史存量可能存在的重名/重复主机库名脏数据；
  - 创建 `uk_host_port_database` 联合唯一索引 `UNIQUE KEY (host, port, database)`；
  - 新增/导入重复连接时触发 `409 Conflict` 或 `IMPORT_CONFLICT` 标准化提示。

## 三、 全量部署与安装操作步骤（全量更新模式）

### 1. 解压全量发布包与部署预检
```bash
# 解压全量发布包
tar -zxvf tdsql-sqlcheck-v1.6.0.2-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.0.2

# 执行部署预检（要求全 PASS，验证依赖与环境健康）
bash deploy/preflight_check.sh
```

### 2. 配置文件校验 (`deploy/.env`)
核对并更新 `deploy/.env` 配置文件中的元数据库与网络参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Admin@1234
```

### 3. 执行全量安装与服务升级重启
```bash
# 执行安装脚本（停止已有服务、覆盖全量代码、重新安装/更新 wheels 依赖、升级数据库 Schema）
sudo ./deploy/install.sh

# 验证部署与健康检查（输出 version: 1.6.0.2）
bash deploy/verify_deploy.sh
```
