## 一、 版本核心变更总结 (升级至 V1.6.1.9)

1. **分布式建表语法深度识别 (R077 / R054 误报消除)**：
   - **HASH 分片表支持**：正确识别 TDSQL 内核 `SHOW CREATE TABLE` 输出的 `TDSQL_DISTRIBUTED BY HASH(col)` 语法，消除 R077“未声明分片键”误报。
   - **广播表（全局表）支持**：正确识别 `shardkey=noshardkey_allset` 哨兵值，将其认定为广播表，消除 R077 与 R054 双双误报。
   - **可信尾部锚定与词法清洗**：仅在列定义闭括号后提取表选项，严格按照 MySQL 规范处理 `-- ` 注释与引号字面量，杜绝 COMMENT 与行注释伪造绕过。
2. **实例解密密钥自动继承与持久化 (`install.sh`)**：
   - 全量升级脚本自动从上一版本目录或 `.env` 继承 `TDSQL_ENCRYPTION_KEY` 与 `data/encryption.key`，彻底避免目录切换导致的实例密码解密失败问题。
3. **在线元数据审核异常防护加固 (`extract-and-audit`)**：
   - 捕获实例连接瞬时网络或认证异常，返回友好的业务 400 提示，杜绝未捕获异常导致的 500 报错。

## 二、 方案 A：全量发布包升级流程 (推荐)

全量发布包采用标准版本目录管理体系（`/opt/tdsql-sqlcheck/releases/v1.6.1.9`），升级过程秒级切换软链，支持一键无损回滚。

### 1. 上传并解压发布包
将 `tdsql-sqlcheck-v1.6.1.9-linux-x86_64.tar.gz` 上传至目标服务器 `/tmp`：
```bash
cd /tmp
tar -zxvf tdsql-sqlcheck-v1.6.1.9-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.1.9
```

### 2. 执行自动化安装脚本
```bash
sudo ./deploy/install.sh --install-dir /opt/tdsql-sqlcheck
```
*注：脚本会自动检测既有环境、继承数据与加密密钥、安装 systemd 服务并启动。*

### 3. 部署后自动化验证
```bash
sudo /opt/tdsql-sqlcheck/current/deploy/verify_deploy.sh
```
输出各检测项全部为 `[PASS]`，且服务版本号确认为 `1.6.1.9` 即表示全量升级成功。

## 三、 方案 B：增量补丁包热更新流程 (仅针对 V1.6.1.8)

若内网当前运行的是 **V1.6.1.8**，可直接使用极小补丁包进行免换目录热更新。

### 1. 上传并解压增量补丁包
将 `tdsql-sqlcheck-v1.6.1.9-patch.tar.gz` 上传至服务器：
```bash
tar -zxvf tdsql-sqlcheck-v1.6.1.9-patch.tar.gz
cd tdsql-sqlcheck-v1.6.1.9-patch
```

### 2. 执行一键打补丁脚本
```bash
# 若当前已在安装根目录下，可直接执行：
sudo ./apply_patch.sh /opt/tdsql-sqlcheck/current
```
*该脚本会自动完成：变动前文件自动备份 ➔ 覆盖更新文件 ➔ 平滑重启服务 ➔ 验证当前版本。*

## 五、 故障回滚操作指南

### 全量包回滚（软链回退）
```bash
sudo ./deploy/rollback.sh --install-dir /opt/tdsql-sqlcheck
sudo /opt/tdsql-sqlcheck/current/deploy/verify_deploy.sh
```

### 增量包回滚（从备份恢复）
进入打补丁时自动生成的 `backup_pre_v1.6.1.9_YYYYMMDD_HHMMSS` 目录，将备份文件拷回原路径并重启服务即可。
