## 二、DEF-A-6.2-b（核心缺口）：转义引号使字面量分段错位

**根因**（与 A §4.2 判定一致）：`_LITERAL_OR_COMMENT_RE` 的单引号分支 `'[^']*'` 不认识反斜杠转义——`'it\'s note0'` 在 `\'` 处提前收束，字符串内外判定整体错位；奇数个 `\'` 时真正的 `PRIMARY KEY (\`id\` DESC)` 被误判为"在字符串内"，剥离失效，退回修复前的 E999 + 误报形态。

**修复**（`parser_legacy.py`，按 A §4.3 已验证方案）：单/双引号分支支持反斜杠转义与双写转义，反引号支持双写：

```
'(?:\\.|''|[^'\\])*'  |  "(?:\\.|""|[^"\\])*"  |  `(?:``|[^`])*`
```

**验证**（新增 4 用例）：
- 奇数个 `\'`（A 核心反例，整表 `COMMENT 'it\'s note0'`）：无 E999、无 R003/R004/R005、R054/R077 不误报；
- 偶数个 `\'` 对照：剥离正常；
- 转义引号字符串内的 ` DESC,` 不被误改；
- 双写引号（`SHOW CREATE TABLE` 输出形态）内的 `DESC,` 不被误改。

## 三、OBS-1（观察项）：CTAS 门控收紧

**修复**：`_strip_index_order_modifiers()` 的 CTAS 判定从 `\bas\s+select\b` 收紧为**语句体含 `\bselect\b` 即不剥离**——覆盖"无 `AS` 写法"与"`AS (SELECT …` 带括号子查询"两种形态；注释内含 select 的语句被误判为 CTAS 时只是回到修复前形态（保守方向，安全）。

**验证**（新增 2 用例）：`CREATE TABLE t2 SELECT … ORDER BY a DESC, b` 与 `CREATE TABLE t2 AS (SELECT … ORDER BY a DESC, b)` 均不剥离，原文保持。

## 四、ENV-1（启动阻断，另案口径外的顺手修复）：MariaDB 默认值引号

**根因**：`_normalize_default()` 未处理 **MariaDB 把字符串默认值加引号返回**（`information_schema.COLUMNS.COLUMN_DEFAULT` 返回 `''`，MySQL 8 返回空串）——A 在 MariaDB 10.11 本地元数据库下，`v4_040` 迁移结构验收报"默认值不符: 期望 '' 实际 \"''\""并失败关闭，全量测试无法完成。

**说明**：该缺陷由 O-23/O-29 的严格验收引入（非本轮改动），但会阻断 MariaDB 元数据库的启动，属我此前改动的连锁影响，故本轮一并修复（A 已标注"与 Q 无关"，修复无争议）。

**修复**（`migrator.py`）：`_normalize_default()` 在归一化前剥一层成对外层引号（`''`→空串、`'x'`→`x`），MySQL 侧为无操作；关键字归一（CURRENT_TIMESTAMP/TRUE/FALSE/NULL）不受影响。

**验证**（新增 4 用例）：MariaDB `"''"` 与 MySQL `""` 归一一致；`"'x'"`/`"x"` 一致；关键字归一不受引号剥离影响；数字默认值两侧一致。
