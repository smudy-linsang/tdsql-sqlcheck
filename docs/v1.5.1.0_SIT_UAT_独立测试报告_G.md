## 2. 详细测试轮次执行记录

- **Round 2 (连接池与配置解析)**：
  - 检查实例配置加载、`connection_registry` 注册与解密机制正常；

- **Round 3 (基本审核入口)**：

### 2.2 SIT 集成测试 (3 轮)

- **Round 1 (自动化测试套件回归)**：
  - 执行 `python -m pytest` 运行全量 1136 项测试用例，**1108 passed, 28 skipped, 0 failed**。
  - 新增的 60+ 项判据反向鉴别、多源保守合并、锁定审计及 ZK 发现用例全部绿灯通过。
- **Round 2 (Proxy 层实测判据逻辑)**：
  - 对比测试 `PR001` (/*proxy*/show status 拓扑签名)、`PR002` (EXPLAIN info列) 和 `PR004` (xa 系统库存在性)；
  - 验证 PR001 为唯一具备输出 `centralized` 正面签名的主判据；PR002/PR004 结构性禁止输出 centralized（未命中即无结论），有效杜绝了因网络抖动或权限裁剪导致漏报的风险。
- **Round 3 (物理真实数据库连库测试)**：
  - **集中式实例 `f9ebc77a` (15002)**：
    - `POST /connections/f9ebc77a/probe-instance-type`
    - 返回：`effective_instance_type = "centralized"`, `matched = "PR001"`, `sources.probe.value = "centralized"`, `conflict = False`。
  - **分布式实例 `5ea70d74` (15005)**：
    - `POST /connections/5ea70d74/probe-instance-type`
    - 返回：`effective_instance_type = "distributed"`, `matched = "PR001"`, `sources.probe.value = "distributed"`, `conflict = False`。
