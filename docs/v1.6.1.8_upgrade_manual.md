## 一、 版本核心变更说明 (V1.6.1.7 ➔ V1.6.1.8)

本版本依据 Codex 与智能体 A 双重两轮安全与架构评审（V3.1 设计规范），彻底解决实例管理权限越界与实例下拉菜单过度耦合问题：

1. **实例管理写操作角色收敛与纵深防御**：
   - 前端实例管理界面根据角色权限动态渲染，普通角色（开发人员、审计员、自定义角色）进入“实例管理”页面时呈现**纯只读态**（写按钮严格为 0）；
   - 后端对所有 14 个实例管理 L3 端点全面实施 `_require_instance_manager(request)`（仅限 `admin` 与 `dba`），L4 高危治理端点维持 `_require_admin(request)` 双保险。
2. **全模块实例读取解耦与精简投影**：
   - 实例下拉菜单所需元数据独立解耦为 `GET /api/v1/tdsql/connections/options`，已认证登录的全角色均可无阻碍获取；
   - 实行严格的 8 字段白名单投影（`id, name, host, port, database, effective_instance_type, is_default, active`），彻底杜绝口令与监控密文暴露。
3. **连接测试 POST 改造与安全增强**：
   - 停用带有 URL 敏感参数的 GET 探针，`POST /test-connection` 升级为接收 JSON Request Body，仅限管理员与 DBA 执行。
4. **前端状态解耦与自动同步**：
   - 前端 `managedConnections` 与 `connectionOptions` 状态分离；任何写操作完成后自动双向同步，并自动清洗悬空已删除实例 ID。

## 三、 增量补丁部署步骤

### 1. 上传与解压补丁包
将 `tdsql-sqlcheck-v1.6.1.8-patch.tar.gz` 上传至目标服务器，并解压：
```bash
tar -zxvf tdsql-sqlcheck-v1.6.1.8-patch.tar.gz
cd tdsql-sqlcheck-v1.6.1.8-patch
```

### 2. 执行自动化部署脚本
运行安装脚本（支持传入目标部署目录，默认当前目录）：
```bash
chmod +x apply_patch.sh
sudo ./apply_patch.sh /path/to/tdsql-sqlcheck
```

该脚本将自动执行以下 4 步：
1. 检查目标目录结构与当前版本；
2. 在 `backup_pre_v1.6.1.8_<timestamp>/` 下自动备份受影响的文件；
3. 将增量文件安全覆盖至目标环境；
4. 优雅重启后台服务并验证 `/health` 探针版本号为 `1.6.1.8`。

### 3. 手动验证升级结果
```bash
curl -s http://127.0.0.1:8000/health
# 预期输出: {"status":"ok","version":"1.6.1.8"}
```
浏览器端强制刷新（`Ctrl + F5`），确认登录页及系统左下角版本号回显为 `V1.6.1.8`。
