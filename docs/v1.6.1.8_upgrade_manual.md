## 一、 版本核心变更总结 (从 V1.6.1.6 升级至 V1.6.1.8)

1. **实例管理权限收敛与全模块实例读取解耦**：
   - 实例创建、编辑、删除、设为默认、建立连接、断开连接、测试连接、ZooKeeper 自动发现与配置等写操作全面收敛至 `admin` 与 `dba`，普通角色（开发、审计员、自定义角色）严格返回 403 Forbidden；
   - 实例下拉数据独立解耦为 `GET /api/v1/tdsql/connections/options`（已登录全角色可用，脱敏密码等敏感字段）；
   - 测试连接由 `GET` 升级为 `POST /test-connection`，密码通过 JSON 请求体传输。
2. **业务操作写权限放行与二级菜单校验**：
   - 慢SQL扫描抓取（`POST /api/v1/tdsql/slow-queries/fetch`）、慢SQL状态标记（`PUT /api/v1/slow-queries/{id}/status`）、扫描结果对比与归档（`POST /api/v1/scan-compare/compare`）、大表清单采集（`POST /api/v1/bigtable/collect`）、即时元数据提取与审核（`POST /api/v1/audit/extract-and-audit`）等业务操作，在 RBAC 一级检查中放行，并交由二级 `role_permissions` 菜单矩阵精准控制。
3. **慢SQL分析报告 PDF 导出修复与编码规范**：
   - 修复 Windows/Linux 字体自动扫描探测逻辑与去重安全集合；
   - 遵循 RFC 5987 标准对导出中文文件名进行 URL 编码（`filename*=UTF-8''...`），彻底解决 Starlette/Uvicorn 底层 Latin-1 UnicodeEncodeError 导致的 404/500 报错。
4. **前端交互与控制台 403 / 404 彻底治理**：
   - `GET /api/v1/admin/logo` 登记为菜单独立只读端点，解决非管理员登录加载主页 Logo 时的 403 报错；
   - 顶栏告警铃铛小红点（`activeAlerts`）增加 `canViewMonitor` 守卫，未授权角色不发起告警请求，避免 403 报错；
   - 大表治理页面“采集大表清单”按钮移除 `canManageInstances` 限制，对具备大表治理菜单权限的所有角色开放；
   - 后端增加 `/favicon.ico` 路由，前端 `<head>` 增加 `<link rel="icon">`，彻底消除浏览器控制台 404 报错。
5. **测试工程质量与夹具隔离机制升级**：
   - 彻底修复测试夹具（fixtures）污染，确保测试前后 `admin` 密码及状态严格快照与还原，用户 `must_change_password` 保持原样，角色权限矩阵精准还原，无测试用户/角色残留。

## 二、 全量升级与部署操作步骤（推荐）

### 1. 解压全量发布包
```bash
tar -zxvf tdsql-sqlcheck-v1.6.1.8-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.1.8
```

### 2. 执行环境与依赖预检
```bash
bash deploy/preflight_check.sh
```
确保所有检查项输出 `[PASS]`。

### 3. 配置确认 (`deploy/.env`)
检查并保留已有生产配置参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Abcd1234
```

### 4. 执行全量安装与服务升级
```bash
sudo ./deploy/install.sh
```
> `install.sh` 脚本将自动停止已有服务、备份旧版本文件、安装全量代码与离线 wheels 依赖、执行数据库 Schema 自动平滑升级并重启服务。

### 5. 部署结果核验
```bash
bash deploy/verify_deploy.sh
```
输出各检测项全部为 `[PASS]`，且服务版本号确认为 `1.6.1.8` 即表示全量升级成功。
