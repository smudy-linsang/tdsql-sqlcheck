## 一、 版本核心变更说明 (V1.6.1.7 ➔ V1.6.1.8)

从 V1.6.1.7 推进升级至 V1.6.1.8，系统完成了以下关键安全与架构解耦改造（落实 V3.1 设计规范）：

### 1. 实例管理写操作角色收敛（权限闭环 + 体验修复）
- **现象回顾**：在旧版本中，若将“实例管理”菜单分配给普通开发人员或审计员，前端页面暴露新建、编辑、删除、设默认等按钮。虽然点击时会被拦截，但极易造成误解，且部分函数缺失响应状态判定。
- **V1.6.1.8 修复**：
  1. 前端对所有写操作按钮严格收敛（仅限 `admin` 与 `dba`），普通角色进入“实例管理”呈现纯只读表格，写按钮数量严格为 0；
  2. 后端对所有 14 个实例管理 L3 端点全面实施 `_require_instance_manager(request)`（仅限 `admin` 与 `dba`），L4 端点维持 `_require_admin(request)` 双保险；
  3. 前端修复 `deleteConn()` 与 `setDefaultConn()` 的状态校验，非 2xx 明确报错。

### 2. 全模块实例读取解耦与精简投影（全局只读上下文保障）
- **现象回顾**：旧版本中，若未给普通角色分配“实例管理”菜单，由于 `/connections` 受菜单权限拦截，导致业务模块（即时审核、扫描任务、大表治理等）中的实例下拉列表为空。
- **V1.6.1.8 修复**：
  1. 新增独立的精简端点 `GET /api/v1/tdsql/connections/options`，全角色已登录用户均可获取；
  2. 底层实行严格的 8 字段白名单投影（`id, name, host, port, database, effective_instance_type, is_default, active`），彻底杜绝口令与监控密文暴露。

### 3. 连接测试 POST 改造与安全增强
- **V1.6.1.8 修复**：
  1. 废弃带有 URL 参数的 GET 版测试接口，防止敏感口令进入 URL 日志；
  2. `POST /api/v1/tdsql/test-connection` 升级为接收 JSON Request Body，仅限系统管理员与 DBA 执行；
  3. 前端 `testConn()` 适配发送 POST 请求。

### 4. 前端双状态解耦与自动同步
- 前端 `managedConnections`（实例管理表格专用）与 `connectionOptions`（全平台下拉框专用）严格分离；
- 新增 `syncConnectionsAfterWrite()` 统一同步器，实例增删改或导入后自动刷新双状态，并自动清洗悬空已删除实例 ID。

## 三、 增量补丁部署步骤

```bash
# 1. 解压
tar -zxvf tdsql-sqlcheck-v1.6.1.8-patch.tar.gz
cd tdsql-sqlcheck-v1.6.1.8-patch

# 2. 执行安装
chmod +x apply_patch.sh
sudo ./apply_patch.sh /path/to/tdsql-sqlcheck

# 3. 验证版本
curl -s http://127.0.0.1:8000/health
# 预期输出: {"status":"ok","version":"1.6.1.8"}
```
