## 2. DEF-A-6.2-c 复测

Q 的实现与上一轮报告 §3.3 给出的修法一致——`select` 判定只在
`_LITERAL_OR_COMMENT_RE` 分段后的**偶数下标普通代码段**内进行。

### 2.1 含 `select` 的普通建表必须仍被剥离（10/10）

| 形态 | 上一版 | 本版 |
|---|---|---|
| 基准：无 select | ✅ | ✅ |
| 表注释含 `'select 结果缓存'` | ❌ | **✅** |
| 表注释含 `'cache for select'` | ❌ | **✅** |
| 表注释中文夹 `'用于select查询'` | ✅ | ✅ |
| 列注释含 `'select 用'` | ❌ | **✅** |
| 反引号列名 `` `select` `` | ❌ | **✅** |
| 列名 `t_select` | ✅ | ✅ |
| 行注释 `-- select 说明` | ❌ | **✅** |
| 块注释 `/* select 说明 */` | 未测 | **✅** |
| **前导**块注释含 select | 未测 | **✅** |

上一版 5 例失效的形态**全部恢复**；另补测的 2 种注释位置也正确。

### 2.2 CTAS 仍不得被剥离（6/6）

| 形态 | 结果 |
|---|---|
| `AS SELECT` | ✅ 未剥离 |
| 无 `AS` 的 CTAS | ✅ 未剥离 |
| `AS (SELECT …)` | ✅ 未剥离 |
| `AS /* 注释 */ SELECT`（把注释塞进 AS 与 SELECT 之间） | ✅ 未剥离 |
| `AS WITH cte AS (SELECT …) SELECT …` | ✅ 未剥离 |
| `CREATE TABLE t (…) SELECT …`（尾部 SELECT） | ✅ 未剥离 |

后三种是我本轮新加的刁钻写法——**收敛之后 CTAS 识别不但没有变弱，反而经受住了更严的探测**。

## 5. 性能：本次提交零开销，累计 +23%（不阻断，建议写进部署文档）

交错测量（消除容器负载漂移，`cbs_coredb` 1958 条 DDL 全量审核，各 3 轮）：

| 版本 | 轮 1 | 轮 2 | 轮 3 | 中位 |
|---|---|---|---|---|
| `f99de2a`（内网现网 v1.6.2.1） | 44.63 | 47.03 | 46.86 | **46.9 s** |
| `974561a`（上一版） | 59.72 | 57.16 | 57.54 | **57.5 s** |
| `4b85e70`（待打包） | 58.61 | 57.59 | 56.88 | **57.6 s** |

* **本次提交开销 ≈ 0**（57.5 → 57.6，落在噪声内）。
* **累计 v1.6.2.1 → 本版约 +23%**（46.9 → 57.6 秒 / 1958 条，约 **+5.5 s 每千张表**）。
* 该增量**不是** A-VERIFY 系列引入的：`_strip_index_order_modifiers` 单独计时
  1958 条共 **553 ms**（282 µs/条，最慢单条 2.2 ms / 31 KB DDL），只占全程约 1%，
  且**未观察到正则回溯病理**。增量来自整个 v1.6.2.2 线的解析加固（DEF-1/DEF-2 + 九轮 UAT），
  该部分已经过 O 的独立质检验收并准予发版。

**建议**：在给内网的部署文档里写一句预期值——
"在线元数据审核约 **30 ms/表**，2000 张表的库约 **1 分钟**"，
避免内网同事升级后看到耗时变长而误以为异常。**不阻断打包。**
