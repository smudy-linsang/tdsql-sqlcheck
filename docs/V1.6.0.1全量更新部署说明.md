## 一、 版本核心变更与架构升级总览 (V1.5.2.5 ➔ V1.6.0.1)

从 V1.5.2.5 全量升级至 V1.6.0.1，系统完成了以下四大核心架构升级与能力拓展：

1. **全新「慢SQL治理 / 原始慢日志」独立子模块 (SSH Exporter V1 协议)**：
   - 解决了现有 `monitordb`（仅有采集时刻）、`digest`（无历史窗口）、`processlist`（无历史记录）在逐条慢 SQL 追溯上的痛点；
   - 引入 CheckSQL 部署机经内网 SSH 只读拉取 Proxy / Gateway 节点原始慢 SQL 日志块的采集链路；
   - 配套 Go 语言静态编译受限导出器 `raw_slowlog_exporter`（安全隔离与白名单限制）；
   - 增加 `slow_log_sources`, `slow_log_source_nodes`, `slow_log_cursors`, `slow_log_events`, `slow_log_runs` 5 张 V7 数据库新表。

2. **统一 SQL 脱敏与 SHA-256 指纹服务 (`sql_masking.py`)**：
   - 实现了全局统一的数字、字符串、Hex 字面量遮蔽，规范模板导出与 SHA-256 指纹计算；
   - 支持 8 KiB 超长模板防爆框截断展示。

3. **便携式 ZooKeeper 真实环境自动发现**：
   - 增强了对 ZK `/tdsqlzk` 节点的只读探查，支持 `noshard` 与 `groupshard` 的解析回写；
   - 增加了只读关断保护与异常自愈降级。

4. **慢 SQL 扫描容错与慢日志时间戳兼容优化**：
   - 慢 SQL 扫描容错增强（防非法 SQL 解析打断扫描）；
   - 真实 TDSQL 慢日志时间戳兼容解析，提供更精准的耗时统计。

## 二、 核心重点：元数据库（System Meta-Database）变更与自动迁移详解

**在从 V1.5.2.5 升级至 V1.6.0.1 过程中，后台服务在启动时会自动安全地应用增量 Schema 迁移文件（`backend/schema/v7/070_raw_slow_log_collection.sql`）以及 `_migrate_old_tables()`，无需运维人员手动执行 SQL 脚本。**

以下为 V1.5.2.5 ➔ V1.6.0.1 元数据库变更清单：

### 1. 新增 5 张原始慢日志系统表 (V7 架构)
- **`slow_log_sources`**：原始慢日志采集源表（记录源名称、SSH 密钥引用、known_hosts 引用、调度间隔、保留天数、启用状态、锁状态等）；
- **`slow_log_source_nodes`**：采集源节点表（记录节点 Key、IP 地址、SSH 端口、远程源 Key、节点别名、Probe 探查证据 JSON、最近一次成功探查时间等）；
- **`slow_log_cursors`**：采集游标进度表（记录节点偏移量 `read_offset`、`file_identity` 文件唯一标识、`generation` 轮转代号、`file_end_hash` 末尾哈希锚点、更新时间）；
- **`slow_log_events`**：解析成功的逐条原始慢日志事件表（记录唯一凭据 `origin_hash`、`event_time` 实际日志记录时间、`query_time` 执行耗时、`rows_examined` 扫描行数、`client_user`/`client_host` 客户端账户信息、`sql_template` 脱敏模板、`sql_fingerprint` 指纹）；
- **`slow_log_runs`**：采集运行审计日志表（记录每次调度的拉取状态、解析事件数、重复被跳过数、失败原因、耗时与错误信息）。

### 2. 存量表字段与索引优化
- 自动执行 `backend/schema/` 目录下的所有增量迁移脚本与防重复补列机制（针对 `users`、`tdsql_connections`、`slow_queries`、`audit_history` 等）；
- `database.py` 内部实现了安全的异常捕获，重复添加已有字段时自动跳过（如 `1060 Duplicate column name`），确保多次升级幂等。

## 三、 全量部署与安装操作步骤（全量更新模式）

### 1. 全量部署包解压与预检
```bash
# 解压全量发布包
tar -zxvf tdsql-sqlcheck-v1.6.0.1-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.0.1

# 执行部署预检（要求全 PASS，验证依赖与环境健康）
bash deploy/preflight_check.sh
```

### 2. 配置文件校验 (`deploy/.env`)
核对并更新 `deploy/.env` 配置文件中的元数据库与网络参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Admin@1234
```

### 3. 执行全量安装与服务升级重启
```bash
# 执行安装脚本（停止已有服务、覆盖全量代码、升级系统数据库表结构）
bash deploy/install.sh

# 验证部署与健康检查（输出 version: 1.6.0.1）
bash deploy/verify_deploy.sh
```

### 4. 部署约束：ZK 标准化导入会话为进程内存（复测 P8）

ZK 发现/导入预览会话（discovery/preview 会话与暂存凭据）保存在**单进程内存**中，
TTL 分别为 10/5 分钟（见设计 §10）。因此：

- **单实例部署（默认形态）**：无影响；服务重启会使进行中的预览失效，属预期行为，重新预检即可。
- **多副本部署（如负载均衡多 worker 进程/多容器）**：禁止直接启用。必须采用会话粘滞
  （同一客户端固定路由到同一进程/实例）或改造为共享带 TTL 的安全会话存储，
  否则"生成预览"与"确认提交"可能落在不同进程导致 410 或凭据丢失。
