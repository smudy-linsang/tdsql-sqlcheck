## 3. 【Q3-M-01｜MAJOR｜本轮新发现】数据分级判错，内网标识符可发往公网分区端点

### 3.1 问题

`copilot.py:1246`：

```python
data_class = "INTERNAL_REDACTED" if body.connection_id else "PUBLIC_HELP"
```

分级依据是"用户有没有选实例"，但**这和正文里实际装了什么无关**。

B-01a 修好之后，一个已获授权的用户**不选实例**问"有哪些实例"，正文里照样会带上
他已授权实例的真实名称、IP、端口、默认库（§2.1 第四行已实测）——
可这时候 `data_class` 是 `PUBLIC_HELP`。

### 3.2 实测后果

构造一个 `data_zone=PUBLIC` / `privacy_profile=PUBLIC_HELP` 的端点：

```
data_class=INTERNAL_REDACTED  → 拒绝 EGRESS_DENIED     ← 闸门本来是有效的
data_class=PUBLIC_HELP        → 放行（可发往 PUBLIC 分区端点）  ← 但分级判错，闸门被绕过
```

也就是说：**内网实例的名称与 IP，会被当成"公共帮助"内容发到公网分区的模型端点。**
这正是 `egress_check` 那条「内部资料决不因故障转移到公网」要防的事。

### 3.3 建议改法（一行）

分级应当看**上下文里到底有没有业务资料**，而不是看有没有传 `connection_id`：

```python
data_class = "INTERNAL_REDACTED" if (body.connection_id or ctx_parts) else "PUBLIC_HELP"
```

`ctx_parts` 非空就意味着感知引擎注入了实例/审核/慢SQL 等内网资料，必须按内网分级走。
纯粹的"什么是分片表"这类问题 `ctx_parts` 为空，仍可走 PUBLIC_HELP，不影响便捷性。

> 缓解因素，说清楚：要触发这条，得有管理员主动创建一个 PUBLIC 分区端点并把它路由上去。
> 内网部署里未必会有。但控制项存在的意义就是防这个，所以我仍判 MAJOR。

## 4. G 额外修好的一个既存缺陷——这个要记一笔

`backend/services/tdsql_connector.py`：

```diff
-            if "BROADCAST" in create_sql_upper:
+            if "BROADCAST" in create_sql:
```

我一开始以为这是把大小写不敏感改成了敏感，准备当回归报上来。**查了之后发现恰恰相反**：

```
改动前：tdsql_connector.py:1567: undefined name 'create_sql_upper'
改动后：（无）
```

`create_sql_upper` 是**另一个函数**（第 410 行）里的局部变量，在 `_detect_shard_info` 里
根本不存在。而该作用域里的 `create_sql` 本身就是 `.upper()` 过的，所以语义完全一致。

也就是说，**广播表判定一直在抛 `NameError`，被外层的 `except Exception: pass` 吞掉了，
这个功能其实一直是坏的**——这是个存在已久的既存缺陷，跟本轮整改无关。
G 是按我上一轮的建议跑 `pyflakes` 时顺手发现并修掉的。**这正是加这道门禁的价值。**
