## 一、 版本核心变更与架构演进总览 (V1.6.1.6 ➔ V1.6.1.8)

从 **V1.6.1.6** 升级至 **V1.6.1.8**（跳过未上线的中间版本 V1.6.1.7），系统完成了重大安全收敛、RBAC 权限重构、业务操作闭环与前端体验治理：

### 1. 实例管理权限收敛与全模块实例读取解耦（核心重构）
- **实例管理写权限严格收敛至 DBA / Admin**：
  - 实例创建、编辑、删除、设为默认、建立连接、断开连接、测试连接、ZooKeeper 自动发现与配置等 14 个写操作端点，在 API 层实施 `_require_instance_manager(request)` 双重校验。
  - 普通角色（开发人员、审计员、自定义角色等）无论是否被分配 `instances` 菜单，调用实例写端点一律**严格返回 403 Forbidden**，彻底杜绝越权修改实例配置。
- **全模块实例只读解耦**：
  - 新增专用只读端点 `GET /api/v1/tdsql/connections/options`，向所有已登录角色提供轻量级实例下拉数据；
  - 严格采用 8 字段白名单投影（`id, name, host, port, database, effective_instance_type, is_default, active`），密码等敏感凭据双重剔除，保障非管理员在即时审核、大表治理、体检、慢SQL、深度诊断等页面能够顺畅选择目标实例。
- **连接测试安全升级**：
  - 废弃原通过 URL Query 参数传递密码的 `GET /test-connection`，升级为接收 JSON Request Body 的 `POST /test-connection`，并严格限制仅管理员与 DBA 可执行。

### 2. 业务操作写权限放行与二级菜单校验机制
- **开发与测试人员业务闭环**：
  - 慢SQL扫描抓取（`POST /api/v1/tdsql/slow-queries/fetch`）、慢SQL状态标记（`PUT /api/v1/slow-queries/{id}/status`）、扫描结果对比与归档（`POST /api/v1/scan-compare/compare`）、大表清单采集（`POST /api/v1/bigtable/collect`）、即时元数据提取与审核（`POST /api/v1/audit/extract-and-audit`）等业务操作端点纳入 `_OPERATIONAL_WRITE_PREFIXES` 并在 RBAC 一级检查中放行；
  - 在二级 `role_permissions` 菜单矩阵中进行精准校验，确保角色仅在其被授予对应菜单权限时可执行相应业务操作。

### 3. 慢SQL分析报告 PDF 导出修复与 RFC 5987 编码规范
- 修复 Windows/Linux 下字体探测逻辑及候选集去重安全遍历；
- 遵循 RFC 5987 标准对导出中文文件名进行 URL 编码（`filename*=UTF-8''...`），彻底解决 Starlette/Uvicorn 底层 Latin-1 `UnicodeEncodeError` 导致的 404/500 导出失败。

### 4. 前端交互与控制台 403 / 404 彻底清爽治理
- **Logo 只读解耦**：将 `GET /api/v1/admin/logo` 登记为独立只读端点，解决非管理员登录加载主页 Logo 时的 403 报错；
- **告警铃铛守卫**：顶栏告警组件与 `loadActiveAlerts()` 增加 `canViewMonitor` 守卫，无监控权限角色不发起告警查询，避免 403 报错；
- **大表采集按钮**：大表治理页面“采集大表清单”按钮移除 `canManageInstances` 限制，对具备大表治理菜单权限的所有角色开放；
- **Favicon 图标**：后端增加 `/favicon.ico` 路由，前端 `<head>` 增加 `<link rel="icon">`，彻底消除浏览器控制台 404 报错。

### 5. 测试工程与夹具隔离机制彻底治理
- 彻底修复测试夹具（fixtures）污染，确保测试前后 `admin` 密码及状态严格快照与还原，用户 `must_change_password` 保持原样，角色权限矩阵精准还原，无测试用户/角色残留。

## 二、 系统元数据库（System Meta-Database）自动迁移

服务启动时，系统会自动安全地应用全套增量 Schema 迁移文件并运行 `migrator.run_migrations()`，无需运维人员手动执行 DDL 脚本：
- **v7 架构**：5 张原始慢日志系统表（`slow_log_sources`, `slow_log_source_nodes`, `slow_log_cursors`, `slow_log_events`, `slow_log_runs`）；
- **v8 架构**：`zk_discovery_config` 表存储 ZK 节点配置、Proxy 映射规则、段替换与富集参数；
- **v9 架构**：`tdsql_connections` 联合唯一索引 `uk_host_port_database`（修正去重判据，绝不按同名误删）；
- **v10 架构**：`zk_discovery_config` 增加扫描富集配置列（`octet_rules_json`, `enrich_enabled` 等），`zk_discovery_import_items` 增加 `name_source` / `databases_source` 留痕列。

## 三、 全量部署与安装操作步骤（内网运维智能体执行）

### 1. 解压全量发布包与部署预检
```bash
# 解压全量发布包
tar -zxvf tdsql-sqlcheck-v1.6.1.8-linux-x86_64.tar.gz
cd tdsql-sqlcheck-v1.6.1.8

# 执行部署预检（要求全 PASS，验证依赖与环境健康）
bash deploy/preflight_check.sh
```

### 2. 配置文件校验 (`deploy/.env`)
核对并更新 `deploy/.env` 配置文件中的元数据库与网络参数：
```ini
SQLCHECK_DB_HOST=127.0.0.1
SQLCHECK_DB_PORT=13306
SQLCHECK_DB_USER=root
SQLCHECK_DB_PASSWORD=tdsql_test_2024
SQLCHECK_DB_NAME=tdsql_sqlcheck
AUTH_ENABLED=true
ADMIN_INITIAL_PASSWORD=Abcd1234
```

### 3. 执行全量安装与服务升级重启
```bash
# 执行安装脚本（停止已有服务、覆盖全量代码、重新安装 wheels 依赖、升级数据库 Schema）
sudo ./deploy/install.sh
```
> ⚠️ **重要提醒**：全量安装时**必须完整运行 `./deploy/install.sh`（或执行 `pip install --no-index --find-links wheels/ -r requirements.txt`）**，以确保所有离线依赖（如 `kazoo`、`reportlab` 等）安装完整。

### 4. 上线最后自检 (必做步骤)
```bash
# 在目标部署机上运行部署校验脚本
bash deploy/verify_deploy.sh
```
`verify_deploy.sh` 会自动检测 Uvicorn 进程、端口监听、版本比对（输出 `1.6.1.8`）与 `/health` 端点，全部输出 PASS 即代表升级成功。
