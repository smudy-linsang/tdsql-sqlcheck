## 1. 需求理解与产品定位

Mr.Linsang 希望借鉴 DB-AIOps 的“Copilot 专家助手”，让 TDSQL 数据库 SQL 审核工具不仅能够发现问题，还能协助用户理解问题、核对证据、准备修改方案和正确使用系统。

产品定位：**懂本工具、懂项目规则、知道当前用户在看什么，并能基于真实证据解释和提出建议的 TDSQL 专家助手**。

不是一个独立聊天网站，也不是放进网页的通用大模型输入框。它需要把“这个按钮怎么用”“为什么这条 SQL 不通过”“两次扫描差异是什么”“任务失败如何排查”连接到现有功能。不得以 AI 的意见代替规则审核、测试结论、生产签署或数据库执行结果。

### 1.1 用户与价值

|用户|典型困难|Copilot 输出|是否代替其决策|
|---|---|---|---|
|开发人员|不理解违规规则、缺少 TDSQL 方言知识|定位违规、解释项目要求、候选修改、待确认语义|否，修改后仍需正式审核|
|测试人员|不知道复测步骤、失败信息难定位|复现步骤、检查清单、已有证据和待补材料|否，不把模拟测试写成实机通过|
|DBA|慢 SQL、统计口径、对比差异难综合判断|证据摘要、风险排序、候选优化及验证路径|否，不自动建索引/删分区/改参数|
|运维人员|执行器、网关上传、部署问题缺乏排查入口|错误码解释、只读排查步骤、相关手册|否，不执行操作系统命令|
|审计/负责人|需要理解依据和未关闭风险|来源、版本、限制、脱敏导出|否，不替代发布门禁签署|
|系统管理员|模型配置和数据出域风险|端点管理、访问授权、额度、调用健康和停用开关|否，不隐式批准公网出域|

### 1.2 成功标准

1. 从当前业务页面打开助手，无须重新描述实例、任务编号和所选规则；用户能预览本次带入的资料。
2. 回答明确区分“项目规则要求”“厂商语法能力”“已有记录”“推测/待验证”，给出可追溯引用。
3. 模型未配置、网络不通、额度耗尽时，原有审核/采集/导出仍可用；助手退为明确标识的本地帮助与规则解释。
4. 新建议不改变原审核结果；与规则引擎冲突时以引擎结果为本工具裁决，同时允许形成误报疑问供人工复核。
5. 新扫描、大文件、6000+ 表或长日志不自动整体进入 Prompt；助手只取有界摘要和用户指定明细。
6. 非授权用户、被撤销权限用户、其他用户会话、未授权实例资料均不能因 Copilot 新增入口而泄漏。

## 2. 对 DB-AIOps 的实证调研

参考仓库：[smudy-linsang/DB-AIOps](https://github.com/smudy-linsang/DB-AIOps)。本机只读检查 `C:/DB_Monitor`，本地 HEAD 与远端 `master` 均为 `a4dfb3b8d102c2fd9af4a37f416c273aa14840e1`。未运行其模型调用、未读取凭据、未改代码。

|已检查实现|确认的能力|本项目采用方式|
|---|---|---|
|`frontend/src/components/CopilotDrawer.jsx`|全局抽屉、实例选择、快捷提问、上下文对话、动作卡片|沿用交互理念，以 Vue 3 + Element Plus 重写，不引入 React|
|`monitor/copilot.py:run_copilot_chat`|按关键词选择证据工具，将资料交给模型；失败时本地模板回答|采用服务端场景路由＋有界证据，增加知识检索、证据权限和持久任务|
|同文件 `get_realtime_ash` / `explain_sql`|缺采样/计划时返回 available=false，不伪造实时结果|保留“无证据即明确未知”；TDSQL 工具没有的 ASH 能力不凭空补造|
|`monitor/llm/router.py`|场景路由、候选提供方、429 冷却、故障转移|采用同一批准数据域内主备切换；禁止隐式遍历所有凭据或退回公网|
|`monitor/llm/providers.py` / `security.py`|模型协议适配、端点检查、服务端凭据、调用日志|采用协议适配层，但端点、TLS、总预算、响应限长重新设计|
|`monitor/models.py` 的 CopilotMemory / CopilotSkill|存在长期记忆和 Skill 数据模型|首期不自动写长期记忆，不启用动态 Skill/MCP 执行；后续走审核发布|
|`monitor/api_views_phase8.py:CopilotChatView`|登录、功能权限及实例可见范围检查|复用“两道权限闸”的原则；TDSQL 现有系统没有可直接照搬的 visible_to 模型|

必须纠正移植时容易产生的误解：

- 当前参考 Copilot 主要是服务端关键词证据路由，并非已具备可安全执行任意工具的自主 Agent。
- 前端保留执行类卡片处理代码，不等于首期应开放目标库写操作；TDSQL 首期卡片只允许导航、查看证据、复制建议、送入审核编辑器。
- 模型切换的价值不能覆盖数据出域审批；内网不可用时自动送外部模型是不可接受的。
- 不能复制固定“性能改善 90%+”文案。没有对照测试，不输出确定比例。
- 最近几条历史消息不是持久会话，更不是可信业务证据；刷新、权限变化及迟到响应必须单独设计。

## 3. 需求清单及首期边界

v1.6.4.0交付首期 **CP-1：受控只读专家助手**。CP-1保留为能力阶段标识，CP-1A/CP-1B/CP-1C均是本版本内部实施阶段，不是另行发布版本；CP-2/CP-3仍不在本次范围内。下表中的 P0/P1 是交付优先级，均属于本版本，不能把安全项目推迟到后续。

|编号|级别|需求|验收抓手|
|---|---|---|---|
|CP-F01|P0|全局助手、独立会话页、上下文入口|所有已展示菜单有帮助入口；实例改变不污染旧会话|
|CP-F02|P0|本地使用指南与规则知识问答|未配置模型仍能查指南、规则及来源|
|CP-F03|P0|解释即时/文件/在线元数据审核结果|规则号、级别、适用架构、行/语句定位与正式记录一致|
|CP-F04|P0|候选 SQL 修改和纯文本复核|不连接目标库；不覆盖原 SQL；明确不能证明语义等价|
|CP-F05|P0|元数据任务失败排查|区分受理失败、执行失败、发布失败、状态未知；不武断认定 OOM|
|CP-F06|P1|慢 SQL / 已有 EXPLAIN 解读|仅用现有指标/用户明确提供的计划；无计划时说明缺失|
|CP-F07|P1|上线检查/大表/四类扫描对比解读|沿用已有比较口径，不把不同实例或规则版本直接判为改善|
|CP-F08|P1|表类型统计解读|保持主表/物理子表/逻辑总表、PARTIAL/UNKNOWN 的现有语义|
|CP-F09|P1|网关日志已有报告解读|取结构化分析摘要；不自动上传原始大日志或整份 HTML|
|CP-F10|P1|其他深度诊断/平台治理/系统管理帮助|都有功能指导；缺持久证据的模块只解释用户选中的资料或引导原页面|
|CP-F11|P0|管理员模型端点/场景配置、连通性自检|只发合成问题；不回显 key；配置变更审计|
|CP-F12|P0|持久会话、异步任务、取消、刷新恢复|同一次提交响应丢失恢复同一 turn；明确新提问生成新 turn|
|CP-F13|P0|引用与安全动作卡片|引用必须对应本次证据；卡片由服务端白名单生成|
|CP-F14|P1|反馈及独立 HTML 建议报告|保留实例连接名称/来源时间/模型/限制；不修改已有 HTML 报告|
|CP-S01|P0|功能、实例、对象、会话四层权限|IDOR、跨用户、权限撤销、ACL 失败全部失败关闭|
|CP-S02|P0|脱敏/数据域审批/出站限制|密钥和原始日志永不出站；禁止跨域故障转移|
|CP-S03|P0|Prompt 注入与输出治理|资料不能提升权限；模型不能自造工具/URL/SQL 执行动作|
|CP-N01|P0|隔离、限流、总预算、可观测性|Web 不等模型长响应；原审核 P95 性能回归门禁|
|CP-N02|P0|离线安装与回退|不新增 Redis/向量库/云存储硬依赖，不引入在线 CDN|

### 3.1 CP-1 明确不做

自动执行 SQL/DDL、自动建删索引/分区、自动改规则集/门禁/权限、自动触发扫描、读业务行数据、自动联网爬取知识、任意 URL/脚本/终端/MCP、自动永久记忆、把问答共享给全员、自动训练/微调、假装实时 ASH 采集。

用户提出上述操作时：解释风险，给出既有页面入口和人工步骤；不以“确认一次”突破本期未开发的能力边界。

## 5. 关键决策与待确认项

已在方案中采用的保守默认：关闭开关、只读建议、内网优先、不自动公网回退、服务端持久化、知识离线发布、模型输出非裁决、无新增重量级基础设施。

已确认：Mr.Linsang于2026-09-13将本次AI Copilot开发定版为 **v1.6.4.0**，不再作为待决项。

仍需 Mr.Linsang / 项目责任方在开工或启用前确认：

1. **模型接入**：获准端点、协议能力、模型名称、证书/受控网络、凭据托管方；不要求在对话中粘贴 key。
2. **数据边界**：默认仅内网脱敏资料；任何公网传输和供应商留存条件需书面批准，未批准不开放。
3. **授权名单和保留期**：首期实例授权默认空、会话私有，建议内容30天、审计元数据180天、管理员可降低但不能静默延长既有用户内容保留。

这些待确认项不阻止开发合成模型适配器、离线知识和安全闭环；但禁止用假端点、未测模型或未批出域配置宣称生产可用。
