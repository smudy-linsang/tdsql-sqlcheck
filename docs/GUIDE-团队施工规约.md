## 关于这份文档

本项目的施工约定过去散落在各版本设计文档的「施工须知」段落里（v1.2 → v1.5.1），查阅时要跨多份文档拼凑，新条目也容易与旧条目冲突。本文档把它们**合并为唯一出处**。

**每一条规约都由一次真实的缺陷或决策产生。** "来源"列不是装饰——它让后来者知道这条规矩防的是什么，从而判断特殊情况下能不能变通。**没有来源的条目不得写入本文档。**

## 一、数据库与 SQL

### R-01 一律使用 `?` 占位符，严禁手写 `%s`

`_MySQLCompatCursor.execute()` 会用正则把 `?` 自动转成 `%s`（`database.py:54-60`）。手写 `%s` 虽因正则只转 `?` 而侥幸能跑，但破坏统一性，且一旦有人调整转换逻辑就会集体失效。

> **来源**：v1.2 元数据库由 SQLite 迁 MySQL 时确立。
> **存量例外**：`zk_discovery_service.py:270`（`e6738ff` 引入）尚未清理，见 §六 遗留清单。

### R-02 Schema 迁移纯增量

只允许 `ADD COLUMN` / `CREATE TABLE IF NOT EXISTS` / `INSERT IGNORE`。**禁止**删列、改名、改类型。任何时候停止读取新列，系统行为即回到上一版本。

> **来源**：v1.3 起确立，v1.4 / v1.5 / v1.5.1 沿用。

### R-03 迁移脚本注释必须整行 `--`，禁止行尾注释

`SchemaMigrator` 先剔除以 `--` 开头的整行，再按 `;` 切割执行。**行尾 `--` 不会被剔除，会连同 SQL 一起被分号切碎。**

> **来源**：v1.3 迁移器实现约束（`schema/migrator.py:50-58`）。

### R-04 迁移列须在 `_ensure_columns()` 补一份双保险

用 `_add_column_if_not_exists()` 写等价声明。两条路径都存在时先执行者生效，后者自动跳过。

> **来源**：v1.2/v1.3 惯例（见 `database.py:502-510` 的 `set_list` / `monitor_*`）。

### R-05 `INSERT` 占位符个数必须与值一一核对

新增列时容易只加列名不加 `?`（或反之）。**这类错误不报错，直接静默错列。**

> **来源**：v1.5 `_save_audit_history` 从 17 个占位符增至 20 个时列为高风险项。

## 二、数据语义

### R-06 NULL 表示"该特性上线前的记录，口径未知"，**严禁回填**

新增的口径类字段（`rule_set_id` / `instance_type` / `zk_instance_kind` …），存量记录一律保持 `NULL`。回填等于**伪造历史评估口径**，让报告不再可复现、可审计。

> **来源**：v1.4 `audit_history.rule_set_id` 确立，v1.5 / v1.5.1 沿用。

### R-13 已被证伪的存量值必须作废 ⭐

> **R-06 的对偶条款，两者方向相反，切勿混淆。**

**凡改变某个字段的生成逻辑，必须同步评估该字段的存量值是否仍然有效；若旧逻辑已被证伪，存量值必须一次性作废（置 NULL 或等价空值）。**

| | R-06 禁止的 | R-13 要求的 |
|---|---|---|
| 动作 | 往权威字段**写入**猜测值 | 把已知错误的值**清除** |
| 后果 | 伪造确定性 | 交还不确定性 |

**判别方法**：问一句——*"新逻辑会不会因为旧值还在，而根本执行不到？"* 若会，必须作废。

> **来源**：v1.5.1 验收（2026-07-29）。v1.5 的恒真探测已给每台实例写入 `detected_instance_type='distributed'`；v1.5.1 的解析器读到该字段有值就直接采用、不再重新探测。**若不作废，新探测逻辑永不执行，所有存量实例的 R077 误报原样保留——包括用户最初报告缺陷的那一台。**
>
> **这类缺陷在全新环境测试中 100% 看不见**（新环境该字段本就是 NULL，走的是重新探测分支），只在升级路径上暴露。v1.5.1 的 1108 项全绿测试完全没有触及它。

## 三、并发与配置

### R-07 生效时延一律写"最长 N 秒/分钟生效"，**严禁写"即时生效"**

生产以 `uvicorn --workers 2` 运行，配置读取带进程内缓存，**不存在跨进程即时一致性**。文档、API 响应 `message`、前端提示语一律遵守。

当前各缓存 TTL：规则集 30s、用户 30s、实例类型 300s。

> **来源**：v1.3.3 会话吊销（写成"即时生效"但实际最长 30 秒）。

### R-08 凭据一律走环境变量，禁止硬编码

包括测试代码中的默认口令。环境差异应通过 `export` 解决，而不是改代码里的默认值。

> **来源**：v1.3.0.1（BUG-130-04）。

## 四、权限与安全

### R-09 敏感接口须"中间件 + 处理函数内显式校验"双保险

权限中间件对**未登记路径默认放行**；且已登记路径的菜单可能同时授予多个角色（如 `instances` 菜单 dba 也有）。因此：

1. 新路径必须登记进 `auth_service._PATH_TO_MENU`；
2. 仅 admin 可用的操作，**处理函数内必须另有** `role != "admin"` 显式校验。

> **来源**：v1.3 `/audit/extracted-reports` 未登记而默认放行；v1.5.1 锁定接口沿用。

### R-10 拼入 SQL 的标识符必须走白名单正则

表名等标识符无法参数化，只能校验。用 `^[A-Za-z0-9_]+(\.[A-Za-z0-9_]+)?$` 一类的严格白名单，**不要用黑名单**。

> **来源**：v1.5.1 `probe-diagnostics` 的 `sample_table`。

## 五、判据、探测与失效方向

> 本节为 v1.5 事故的直接产物，是本文档中**最贵的一组规约**。

### R-11 判据必须有实测依据，未经实测不得进入详细设计 ⭐

凡涉及"从外部系统探测事实"的判据，设计阶段**必须附上真实环境的实测输出**。不接受"按文档应该有差异"。

**采纳标准（三条全满足）**：

1. 两类目标上**实测输出确有差异**，`evidence` 字段写明实测日期与数据出处；
2. 差异**方向明确**：命中即为**阳性证据**；
3. **未命中时不得作反向结论**，必须返回"无结论"下沉至下一判定源。

> **来源**：v1.5 凭"集中式实例 = 直连 MySQL 无 Proxy"这一未经验证的架构假设写判据。真实情况是 TDSQL 两类实例统一由 Proxy 接入，且 `/*proxy*/` 只是一个 SQL 注释——**判据恒为真，探测退化成常量函数**，核心目标完全未达成。

### R-12 测试必须包含反向鉴别用例 ⭐

**对两类目标各跑一次，断言结论"不同"。** 仅断言"某类返回某值"的用例，对常量函数完全无感。

> **来源**：v1.5 的 `test_probe_distributed_when_proxy_ok` 是全绿的——因为它逐字实现了错误的规格。**测试只验证了"实现符合设计"，从未验证"设计符合现实"。**

### R-14 采集环境必须等于判定环境

排障或验证判据时采集的数据，必须用**系统自身的连接方式、账号、驱动、端口**采集。

> **来源**：v1.5.1 实测。同一条 `/*proxy*/show status`，从后端 socket 采到 **458 行**，经 Proxy 端口只有 **2 行**。从错误入口采回的数据无法迁移到生产判定。

### R-15 失效方向不对称时，一律偏向"可见的错"

当两个方向的误判后果不对称时，设计必须偏向**看得见、可纠正**的那一侧。

本项目的具体口径：

| 误判方向 | 后果 | 可见性 |
|---|---|---|
| 判成分布式 | 多跑规则 → 误报 | **一眼看见**，可纠正 → **可接受** |
| 判成集中式 | 少跑 27 条 → 漏报 | **完全不可见**，直接放行风险 → **禁止** |

由此派生的具体做法：**保守合并**（任一源判分布式即取分布式）、**阳性优先于阴性**、**规则适用域存疑时归 ALL**、**兜底方向取 `distributed`**。

> **来源**：v1.5 设计 §2.2 确立；v1.5.1 因 G 提案代码中 `else: return "centralized"`（一次网络抖动即可静默关闭 27 条规则）而强化为硬性规约。

### R-16 "未命中"不等于"反向成立"

只有命中**该结论自身的正面签名**才可下该结论。区分二者的方法是问：*这个"没看到"，是因为它不存在，还是因为我看不见？*

**反例（禁止）**：`SHOW DATABASES` 没返回 `xa` 库 → 判集中式。
**为什么错**：`SHOW DATABASES` 只返回**账号有权限看到**的库。窄权限账号在真正的分布式实例上也看不到 `xa`——**等于让账号权限决定审核口径**。

**正例（允许）**：`/*proxy*/show status` 返回单 SET 且无 `cluster` 行 → 判集中式。该输出由 Proxy 生成，**不受账号权限裁剪**，是"单 SET 拓扑"的结构性正面签名。

> **来源**：v1.5.1 PR004 判据设计。
