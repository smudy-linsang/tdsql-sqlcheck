## 3. UAT 发现

### UAT37-01（MAJOR，用户可直接感知）存量历史记录未订正，列表呈现新旧混排

**现象**：用户打开「历史元数据审核记录」，会同时看到

| 报告ID | 提取生成的SQL文件 | 提取时间 | 判定 |
| --- | --- | --- | --- |
| #1386 | `extracted_uat_d_1636_dist_20260912_161741.sql` | 2026-09-12 16:17 | ✅ 新规 |
| #1385 | `extracted_uat_d_1636_dist_20260912_161634.sql` | 2026-09-12 16:16 | ✅ 新规 |
| **#22** | **`extracted_uat_d_1636_dist_2ebe5fd3.sql`** | **2026-09-11 16:14** | ❌ 存量（UUID 形态 + 早 8 小时） |
| **#8** | **`extracted_uat_d_1636_dist_3043e1af.sql`** | **2026-09-11 14:22** | ❌ 存量 |
| **#4** | **`extracted_uat_d_1636_dist_a0278f77.sql`** | **2026-09-11 14:18** | ❌ 存量 |

**8 小时错位的硬证据**（用同任务的产物文件头反证）：

| 报告ID | 列表显示 `created_at` | 同任务 `schema.sql` 文件头「提取日期」 | 差 |
| --- | --- | --- | --- |
| #22 | 2026-09-11 **16:14** | 2026-09-12 **00:14:16** | **8 小时** |
| #8 | 2026-09-11 **14:22** | 2026-09-11 **22:22:38** | **8 小时** |
| #4 | 2026-09-11 **14:18** | 2026-09-11 **22:18:09** | **8 小时** |

**影响**：这正是 Mr.Linsang 最初反映的两件事（报告命名被改乱、时间对不上）在**存量记录**上的残留。产品代码修复只对**新数据**生效。

**唯一处置手段**：`deploy/patch_v1637_source.sql`。该脚本当前**不可执行**——两处 BLOCK 级缺陷（MySQL `DATE_FORMAT` 的 `%M` 应为 `%i`，会把畸形名写进生产；`OR id = 1377` 分支不幂等，重复执行再叠加 8 小时），详见《RETEST-v1.6.3.7-…-SIT复测报告-D》§3.3。

**照图施工级修正 + 执行后必须核验的断言**：

```sql
-- 修正 1（格式）：MySQL 的分钟是 %i（%M 是月份英文名）
SET source = CONCAT('extracted_', db_name, '_',
                    DATE_FORMAT(created_at, '%Y%m%d_%H%i%s'), '.sql')

-- 修正 2（幂等）：以备份表锁定一次性目标集 + 形态判定兜底，替代无条件的 OR id = 1377
WHERE audit_type = 'extracted_schema'
  AND id IN (SELECT id FROM _bak_v1637_audit_history)
  AND source REGEXP '^extracted_.+_[0-9a-f]{8}\\.sql$'
```

```sql
-- 【必须新增】执行后断言 1：改名结果全部合规（期望 0）
SELECT COUNT(*) AS bad FROM audit_history
WHERE audit_type = 'extracted_schema'
  AND id IN (SELECT id FROM _bak_v1637_audit_history)
  AND source NOT REGEXP '^extracted_.+_[0-9]{8}_[0-9]{6}\\.sql$';

-- 【必须新增】执行后断言 2：再执行一遍不漂移（比对两遍的 created_at 完全一致）
SELECT id, created_at FROM audit_history
WHERE id IN (SELECT id FROM _bak_v1637_audit_history) ORDER BY id;
```

> 验收要求：脚本修正后**必须实跑两遍**，两条断言均通过，再由 D 复验后方可在生产窗口执行。

### UAT37-02（NIT，体验）下载按钮用 `window.open` 取文件，会闪出空白标签页

本次测得两次点击均产生一个 popup（初始 URL 为空），文件内容与文件名完全正确（`Content-Disposition` 已带 `attachment`）。真实浏览器表现为"闪一下空白页随后自动关闭并开始下载"，且**不进入浏览器下载管理器记录**。建议后续改为 `<a download>` 或 `location.href` 触发；不阻断本次准出。

### UAT37-03（NIT，契约）文件名时间戳与文件内「提取日期」存在 1~2 秒差，可能随实例连接耗时增长

本轮实测：文件名 `…_161741.sql` ↔ 文件头 `16:17:43`（**2 秒**，恰在 §3.1「≤2 秒」上限）；SIT 端到端样本为 1 秒。因文件名取"任务开始时间"、文件头取"实际连接后提取时间"，大库首连慢时该差值会进一步增大。**建议**：后续若要新增"文件名 vs 文件头一致性"断言或界面提示，须放宽阈值或统一两者取值口径，避免误判。
