# TDSQL Copilot 专家助手高阶设计

版本：CP-HLD / Rev.A；日期：2026-09-12；设计：O；提交：Mr.Linsang。

状态：待评审、文档设计；发布版本待定。上接[需求与规划](PLAN-AI-Copilot-需求分析与总体规划-O.md)，下接[施工详细设计](DETAIL-AI-Copilot-专家助手详细设计说明书-O.md)。

## 1. 设计基线

TDSQL 当前本地基线 `b6ce21bbcd731fe4f541c6ec09cd7a1316e52de3`，应用版本1.6.3.7；其中最新提交为既有生产部署文档。业务技术栈是 FastAPI、Vue 3全局脚本、Element Plus、PyMySQL/MySQL元数据库，非 Django/React。现有 `httpx`、`pydantic`、`cryptography` 可支撑首期，不需要引入大模型 SDK、Redis、LangChain 或向量数据库。

DB-AIOps 参考基线为 `a4dfb3b8d102c2fd9af4a37f416c273aa14840e1`；仅复用经过审视的设计理念，不能直接拷贝 ORM、数据范围接口和 UI 组件。

## 2. 架构与信任边界

```text
用户：全站抽屉 / 会话页 / “让 Copilot 解读”
  │ 短请求 + Bearer；只传问题、明确选择的对象引用
  ▼
Copilot API（鉴权、实例授权、预览、幂等受理、查询/取消）
  │ 原子写会话 / turn / 预算；不等待模型、不连接目标实例
  ▼
MySQL 元数据库：独立 copilot_* 数据域
  ▲                         │ 仅已受理任务
  │ 心跳/状态/结果            ▼
  └───────────── 独立 copilot-runner（并发默认2）
                     ├─ 场景路由 / 权限复核
                     ├─ 本地帮助与规则知识包
                     ├─ 既有记录只读适配器 ── 审核 / 慢SQL / 对比 / 表统计 / 网关
                     ├─ 脱敏与出域策略 ── 明确批准的模型网关
                     ├─ 输出结构/引用/建议校验
                     └─ 安全动作卡片 / 独立建议报告

原有审核引擎 / 元数据 runner / 采集流程 / 门禁 / 目标 TDSQL
继续按原入口运行；不存在“Copilot → 任意 SQL / 终端”的连线。
```

资料来自用户文本、数据库注释、SQL、日志、模型返回和知识包，信任级别不同。任何资料都不能改变系统提示词、权限、工具定义、端点地址、实例选择或提交状态。

## 3. 核心架构决策

|ADR|选择|理由及代价|
|---|---|---|
|01|独立功能，不进入审核同步关键路径|模型失败不改变审核结论；需增加独立进程与部署校验|
|02|CP-1 使用服务端固定场景工作流，不开放模型自主工具循环|降低不确定性与越权面；自由跨模块调查留待后续独立立项|
|03|POST返回202＋GET短轮询，首期不做逐 token 流|可靠恢复比打字动画重要；刷新不重发推理，响应不会悬挂数分钟|
|04|MySQL持久 turn＋原子全局控制行，默认2个执行、4个未结束任务|兼容多 Web worker且不增加Redis；适合本项目低并发专家问答，非大规模多租户聊天平台|
|05|按批准模型网关的 OpenAI-compatible Chat Completions 接入|适配常见内网服务；“兼容”须做契约测试，不能只看产品名|
|06|原生 Responses / 其他厂商原生协议属于后续适配包|首期不混合多个协议；新增适配不修改业务工具和权限逻辑|
|07|离线知识包＋字段精确检索/中文双字词 BM25，无运行时抓网|便于内网部署和版本核验；不能回答未收录的新资料时明确未知|
|08|助手专用实例授权＋源模块/对象权限＋会话所有者|现有菜单权限不等于逐实例授权；助手先采取更窄范围，不改造全站ACL|
|09|新凭据使用独立 AES-GCM 密钥环，失败关闭|现有 security_service 存在兼容性降级路径，不直接用于新模型密钥|
|10|结构化证据优先，旧HTML不做全量反向解析|防止大报告重读、XSS和指令注入；资料不足提示回原页面|
|11|用户显式送入原审核编辑器，无目标库执行|保留人的意图和既有审核入口；不是自动修复平台|
|12|所有模型回答均为建议；无模型是 LOCAL_ONLY / DEGRADED，不伪装AI成功|可追溯与可解释，牺牲不可靠的“无缝降级”表现|

## 4. 子系统职责与复用边界

### 4.1 前端

新增 `copilot.js`、`copilot.css`，作为现有 Vue setup 的组合模块使用，不复制整个 app.js。保留静态离线供应方式。入口包括页头全局按钮、侧栏“Copilot专家助手”、已有结果卡旁的解读按钮。

`ContextBridge` 只提供页面键、选中记录ID、草稿文本及表单修订号，不能发送 token/连接配置对象/整份结果。实例与资料预览来自服务端；切实例新建上下文，不把当前页面实例套到历史消息上。

### 4.2 控制层

API负责鉴权、预览、受理、查询、取消、导出和管理员配置。所有成本性操作有服务器幂等键。会话/任务的身份、连接名称快照、规则版本和资料哈希受服务端控制。

正文存本机加密介质；浏览器只缓存用户命名空间下的会话ID和未决提交标识。登出停止轮询并清理视图，历史正文不保留在浏览器存储。

### 4.3 执行层

独立 runner：领取任务前再次鉴权→获取已批准有界证据→本地检索→执行最终出域检查→调用模型→校验输出→原子发布。故障或重启不能把旧任务自动重新发送给供应商；过期任务标记中断，用户明确新提问才能重试。

仅安全的元数据库查询和受限纯文本审核可由助手执行。当前一些“service读取”会触发实例探测、全量反序列化或历史写入，因此适配器必须逐一选择纯读取/纯计算路径，不能直接调用名字类似的API函数。

### 4.4 模型与知识

首期模型只接收已经脱敏且获准的资料，并输出限定JSON结构。证据和动作卡片由本系统生成，不使用模型提供的URL或权限声明。

知识有独立的来源、产品族、版本范围、有效状态、审查人和内容hash。项目规则与厂商文档分域：厂商允许某语法不等于项目允许；项目禁止某用法也不等于 TDSQL 语法错误。TDSQL MySQL、TDSQL-C、Boundless和原生MySQL不能混用。

## 5. 数据流和正常/异常状态

```text
预览 PREPARED（120秒有效，不花模型额度）
    → 用户确认本次资料和目标
    → turn ACCEPTED（幂等受理）
    → RUNNING: EVIDENCE → RETRIEVAL → MODEL → VALIDATING
    → SUCCEEDED / LOCAL_ONLY / DEGRADED / FAILED / CANCELLED / INTERRUPTED
```

只在最终结构和引用校验完成、结果事务提交后显示成功。HTTP202只表示受理；退出抽屉只是停止视图轮询，不等于取消任务；显式“停止本次回答”才提交取消。

提交响应丢失：用相同 client_request_id 和相同 preview_id 重放；服务端先查同一所有者幂等记录，再做新任务容量检查，返回原 turn。不得用“该用户最新任务”替代本次提交身份。

## 6. 安全模型

四道闸：**是否能用助手 → 是否获准带入该实例 → 是否能读取该源对象 → 是否拥有该会话**。管理员配置权不自动赋予阅读其他用户会话正文的权限。

三类输入：PUBLIC_HELP、INTERNAL_REDACTED、RESTRICTED。默认只有部署批准的 INTERNAL 网关能接 INTERNAL_REDACTED。PUBLIC外部端点在首期只接批准知识包中的固定公共问题，不接用户自由问题/历史/业务资料；任何不确定数据分类退回本地帮助，不自动放宽。

既有账号以username为主键，新增Copilot subject代际身份并接入账户创建/删除事务，不用同名字符串决定历史会话归属。模型凭据与会话资料都按不可变subject做授权及加密绑定，删除重建账号不能继承旧问答。

首期没有高风险动作工具，Prompt注入即便成功影响措辞，也不能获得SQL执行、文件读写或出网任意地址能力。引用验证只证明引用存在，不证明模型推理正确；因此另设语料评测与UAT。

## 7. 运行与容量

独立 runner 不复用 `metadata_audit_slot`、网关锁、元数据 worker或扫描槽。总时限、模型连接池、进程资源、配额都有界。启用2个Copilot推理并同时运行既有元数据审核时，原接口P95不得比同场景关闭Copilot劣化超过10%（控制测试条件，内网实测）。

模型配置关闭是运行降级；新增 Schema 迁移失败仍遵循现有数据库迁移失败关闭原则，不能宣称“数据库坏了也完全不影响系统”。发布必须在升级前验证新表结构、离线依赖和回退路径。

## 8. 开发准入和验收接口

需求、参数默认值、DDL字段、API、前端状态、异常码、复用函数、责任分解和反例验收全部下沉到详细设计。评审必须至少覆盖：

- 数据不能越权、出域不越界、密钥不降级。
- 长响应不占 Web 请求、刷新/幂等/取消/权限撤销不串会话。
- 模型不能更改原审核记录，未知不能转为0/正常/通过。
- 安装、增量升级、补丁、回滚五类发布检查含独立runner，不能只改install脚本。
- 使用真实获准模型和内网样本验证，而不是仅凭mock模型和单元测试宣布投产。
